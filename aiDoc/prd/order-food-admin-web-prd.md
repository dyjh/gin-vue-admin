## 2. 背景与定位

“来干饭”小程序已经完成前端页面、主要交互和 Mock 阶段，下一阶段需要建设真实后端与管理后台。后台管理端不是小程序功能的简单复制，而是平台运营、基础配置、内容安全、AI 成本控制和问题排查的工作台。

后台的核心价值：

1. 让运营人员维护平台级分类、标签、单位、推荐内容和官方菜品。
2. 让管理员管理用户状态、积分和违规处理结果。
3. 让技术或运营人员配置 AI 供应商、模型、能力、默认或自定义提示词、费用和限额。
4. 让客服或管理员能够定位饭局、采购、通知和 AI 调用问题。
5. 让授权管理员查询全部用户菜品、菜谱及偏好画像，定位私有内容和偏好聚合问题。
6. 对关键管理操作和敏感内容查看保留可追踪、可审计的记录。

后台可以在独立敏感权限下查询、核对并处理违规的个人菜品、个人菜谱，但不替普通用户新增、编辑、调序、公开或恢复这些内容，也不修改饭局点选结果或采购清单。

## 4. 产品目标

### 4.1 第一版目标

- 后台可以独立完成平台基础数据配置。
- 推荐内容从“允许被发现”的候选池中精选，不额外建立公开审核队列。
- 用户禁用、积分调整、违规处理和推荐上下线具备审计记录。
- 授权管理员可以查询全部用户菜品和菜谱，并在不代用户编辑的前提下处理违规内容。
- 超级管理员可以在用户详情查看由打卡等证据聚合的只读偏好画像。
- AI 六项业务能力分别配置模型、提示词、计费和限额，由一个平台总开关整体开放或关闭，不提供单项开关。
- 管理员可以只读查看饭局关键链路，定位点餐、确认菜单和采购清单问题。
- 所有列表使用服务端分页、稳定排序和明确的空状态、异常状态。

### 4.2 非目标

第一版不包含：

- 后台代替用户创建或编辑未公开菜品、个人菜谱。
- 管理员直接修改参与者点选结果、最终份数或采购项。
- 重新开启已关闭饭局，或绕过业务状态机强制推进饭局。
- 多人实时协作采购、库存、价格、结算和仓储管理。
- 脱离能力模板、变量白名单、测试和变更审计的低约束 Prompt IDE。
- 独立 BI 平台、数据仓库或微服务拆分。
- 作者主页、关注、评论、点赞和社交关系运营。

## 5. 用户角色与权限

### 5.1 超级管理员

- 拥有后台全部菜单和操作权限。
- 管理管理员角色、API 权限和菜单权限。
- 配置 AI 供应商密钥引用、模型、能力提示词和系统级开关。
- 拥有提示词正文查看、编辑和测试权限；其他默认角色不读取正文。
- 可执行用户禁用、严重违规删除和复制链处理。
- 可查看用户私有菜品、私有菜谱和偏好画像；敏感详情访问均记录审计。

### 5.2 运营管理员

- 管理分类、标签、单位、官方菜品和推荐位。
- 从可发现候选池中精选或取消推荐。
- 查看用户、积分、饭局、采购和运营指标。
- 不可查看供应商密钥明文，不可管理系统管理员权限。

### 5.3 内容安全管理员

- 查看图片审核记录、可发现内容和违规处理记录。
- 查看全部用户菜品和菜谱的私有详情。
- 关闭允许被发现、取消推荐、软删除违规内容。
- 对严重违规源菜品发起复制链处理。
- 每次处理必须填写原因和违规类型。

### 5.4 客服只读角色

- 只读查看用户、积分流水、饭局、采购、AI 调用和通知发送记录。
- 不可修改积分、用户状态、推荐状态或系统配置。

### 5.5 权限原则

- 菜单权限控制页面可见性。
- API 权限控制真实操作能力，不能只依赖前端隐藏按钮。
- 高风险操作增加按钮级权限和二次确认。
- 管理操作记录管理员、目标对象、变更前后摘要、原因、时间和请求追踪 ID。
- 私有菜品、私有菜谱和偏好画像使用独立于普通用户详情的读取权限；敏感详情访问也写审计。
- 角色、菜单、按钮和 API 权限均由 GVA/Casbin 配置，默认角色只是可编辑模板，业务代码不写死角色授权。
- 自动注入的第一个管理员账号绑定“来干饭超级管理员”，拥有当时及以后新增的全部 `orderfood` 权限。
- 模型新增或编辑同时要求模型写权限和供应商读取权限；能力编辑同时要求能力写权限和模型读取权限；提示词读取、编辑和测试分别校验独立权限。

## 7. 运营概览

### 7.1 页面目的

快速判断核心业务是否正常运行，优先展示可行动的信息，不建设复杂 BI 看板。

### 7.2 第一版指标

- 今日新增用户、活跃用户。
- 新用户首次创建菜品率。
- 可用菜品数、允许被发现菜品数、推荐中菜品数。
- 今日创建饭局数、加入人数、确认菜单数、采购清单生成数。
- 今日打卡数、获得积分、消耗积分、退款积分。
- AI 调用成功率、失败率、平均耗时、当日估算成本。
- 当前平台总开关、紧急停用状态和生效用户数量。
- 违规处理任务异常数、图片审核失败数。
- 订阅消息发送失败数。
- 待退积分异常数、供应商或模型连续失败告警；连续失败只告警，不自动关闭平台总开关。

### 7.3 交互规则

- 默认查看今日，可切换近 7 天和近 30 天。
- 指标卡可跳转到对应筛选后的列表。
- 数据刷新失败时保留上次成功数据并显示更新时间和错误提示。
- 指标只用于运营判断，不作为财务结算依据。

## 8. 用户与积分

### 8.1 小程序用户列表

筛选条件：

- 用户 ID、昵称。
- 正常、已禁用。
- 增强能力有效状态。
- 注册时间、最近登录时间。
- 积分区间。

列表字段：

- 用户公开 ID。
- 头像、昵称。
- 当前积分。
- 增强能力有效状态及来源：平台总开关或紧急停用。
- 累计打卡天数。
- 菜品数、饭局数。
- 状态、注册时间、最近登录时间。

操作：

- 查看详情。
- 进入该用户的全部菜品或全部菜谱筛选结果。
- 禁用或恢复用户。
- 进入积分调整。

禁用用户时必须填写原因。禁用不自动删除或下架既有内容，但会同步取消该用户发起的 `collecting`、`closed`、`confirmed` 饭局，取消原因为 `creator_disabled`；已确认饭局的最终菜单快照和采购清单保留只读，并通知参与者。确认页需展示受影响饭局和参与者。

### 8.2 用户详情

展示：

- 基础资料和账号状态。
- 脱敏微信身份及最后登录时间。
- 增强能力有效状态和计算来源。
- 当前积分与最近积分流水。
- 菜品、菜谱、饭局、打卡数量摘要。
- 只读偏好画像：画像状态、累计打卡天数、常用与常点标签、常用配料、口味摘要、忌口或偏好备注摘要、最近更新时间。
- 偏好证据数量摘要：打卡、采用推荐、保存菜品、点菜和反馈等来源；不展示打卡原图和完整证据明细。
- 最近 AI 调用和退款记录。
- 最近通知。
- 管理操作记录。

后台不在此页直接编辑用户私有菜品内容。

偏好画像由打卡等多类证据异步聚合，不把一次图片识别结果直接覆盖为长期偏好。用户主动填写的过敏、忌口和饮食限制必须与系统根据使用记录归纳的偏好分开标识。增强能力或打卡图片分析关闭后保留历史画像，并显示“当前已暂停更新”。首版不提供编辑、手动重算或删除画像。

偏好画像使用独立读取权限，默认只授予超级管理员；每次打开该标签记录管理员、用户、时间和请求 ID。普通 `user:read` 不自动获得画像读取能力。

用户详情不提供单用户能力开关。积分入口、打卡奖励和偏好分析统一跟随平台总开关；全局紧急停用时全部关闭。

### 8.3 积分流水

- 支持按用户、类型、业务场景、关联对象、时间和请求幂等号查询。
- 类型统一为获得、消耗、退款、人工调整。
- 消耗与退款通过关联流水 ID 建立关系。
- 流水不可编辑或物理删除。

### 8.4 人工积分调整

- 输入用户、调整方向、积分数和原因。
- 调整后写入流水并更新用户当前积分。
- 扣减后余额不得小于 0。
- 提交前展示调整前后余额。
- 同一次提交使用幂等键，防止重复点击产生多条流水。

### 8.5 积分规则

- 第一版只配置“每日首次做菜打卡奖励积分”，默认 1 分，允许范围为 1—100。
- 编辑时填写变更原因，保存成功后立即生效，不设置草稿、发布或历史版本页面。
- 新配置只影响保存后的新打卡，不追溯历史打卡，也不重算已有积分流水。
- 平台整体能力关闭时仍保存打卡，但不发放奖励；重新开启后按当前积分规则执行。

## 9. 菜品运营

### 9.1 用户菜品

覆盖所有用户、所有状态和来源的个人菜品，包括手工创建、官方或推荐副本、保存增强建议形成的菜品及已软删除审计记录。官方菜品本体不在本页，用户复制出的个人副本在本页。

支持：

- 按菜品、用户、状态、删除状态、发现状态、来源、分类、标签、图片审核状态和时间查询。
- 查看内容、归属与来源、复制链摘要、菜谱与饭局引用、图片审核及处理记录。
- 从用户详情带用户 ID 进入，从菜谱详情带菜品关系进入。
- 对违规内容执行关闭发现或软删除，并同步下线源头关联推荐；严重违规复制链处理仅限专门权限。

私有、草稿和已删除菜品的封面、配料及步骤使用独立读取权限，查看详情写访问审计。管理员不能新增、编辑、替用户改变状态或公开内容，也不能恢复、批量处理或导出。

### 9.2 用户菜谱

覆盖所有用户的个人菜谱及其菜品关系，支持按菜谱、用户、所含菜品、菜品数、删除状态、失效菜品和时间查询。

- 列表不展示备注全文，也不提供备注全文模糊搜索。
- 详情展示名称、备注、按顺序排列的菜品、关系审计、删除信息和管理员操作记录。
- 违规处理只软删除菜谱本身并通知用户，不删除其中菜品，不改变历史饭局和采购快照。
- 管理员不能改名、改备注、增删菜品、调整顺序、恢复或导出。

私有备注和菜品清单使用独立读取权限，查看详情写访问审计。如果违规对象是某道菜，必须转到“用户菜品”处理。

### 9.3 可发现候选池

候选来源仅包括：

- 状态为可用。
- 用户主动开启“允许被发现”。
- 未被违规处理删除。
- 不是平台推荐副本或 AI 推荐副本。

列表展示：

- 封面、菜名、分类、标签、作者。
- 允许被发现开启时间。
- 被点人数、被复制次数。
- 是否已被精选、当前推荐位置。

操作：

- 查看完整只读详情。
- 精选到推荐。
- 因违规处理关闭允许被发现。
- 对违规内容执行软删除。

本页不提供“审核通过/驳回”。管理员精选到推荐本身就是内容把关行为。

### 9.4 推荐精选

推荐记录具有独立状态：

- `draft`：已选中但未发布。
- `published`：正在小程序推荐位展示。
- `offline`：已下线。

支持：

- 设置推荐位和排序。
- 发布、下线、重新发布和排序。
- 查看来源作者或“来干饭官方”来源。

创建推荐只能从“可发现候选池”和“官方菜品”对应行发起，来源自动带入；推荐列表页页头不提供“新建推荐”。来源自创建后不可替换。

发布或重新发布只做一次确认，不提供发布预览接口，不要求填写发布原因。服务端在发布事务中实时校验来源、封面、推荐位容量和记录版本。手动下线必须填写原因；来源失效导致的自动下线使用固定系统原因。`offline` 记录只允许编辑排序和展示说明，来源恢复有效后重新发布同一记录。

用户关闭允许被发现、编辑源菜品、删除源菜品或被违规处理时，相关在线推荐自动下线。推荐操作均保留审计记录。

### 9.5 官方菜品

- 由平台直接发布，作者展示为“来干饭官方”。
- 必须有封面、分类、基础份量、配料和做法步骤。
- 可作为推荐内容发布。
- 用户加入菜品库后生成个人副本。
- 个人副本默认未公开，允许编辑，永久不能再次开启允许被发现。
- 官方菜品新建和编辑页内提供封面“上传/选择”抽屉，不新增独立官方媒体库菜单。
- 管理员上传封面不调用阿里云审核，固定记为平台图片、`admin_upload`、`official_dish_cover`、`not_required`；服务端仍校验文件格式、大小、尺寸、场景和平台归属，并记录管理员、时间和文件信息。
- 平台封面允许复用；替换封面或软删除菜品不立即删除图片资源。
- 编辑或删除存在在线推荐的官方菜品时，确认框显示“将下线 N 条推荐”；确认后保存或软删除并自动下线推荐，不影响用户副本、历史饭局和采购快照。

官方菜品不是管理员代用户创建的私有菜品。

### 9.6 分类、标签和单位

共同能力：

- 新增、编辑、启用、停用、排序。
- 名称唯一校验。
- 已被业务数据引用时不允许物理删除，只能停用。
- 停用项不再出现在新建表单中，历史数据继续展示原值。

分类用于菜品侧栏和筛选；标签最多由用户选择 3 个；单位用于配料数量表达。

### 9.7 标准菜品索引

标准菜品索引只维护生成建议校验所需的数据，不保存完整菜谱，也不进入可发现候选池、平台推荐或官方菜品。

页面分为：

- 菜品索引：标准菜名、别名、菜系、平台分类、允许食材、必需食材、来源和启用状态。
- 食材词库：标准食材名、别名和启用状态。
- 生成建议校验：编辑“是否使用菜品索引和食材词库校验生成结果”，保存后立即生效。

关闭该开关只跳过菜名、菜系和食材词库匹配；字段结构、分类、标签、单位、配料与步骤一致性始终校验。开启后，首次生成或校验失败在同一笔使用中固定再尝试 1 次；两次都失败才退款且不占免费次数。关闭后只尝试 1 次，失败同样退款且不占免费次数。

新环境默认关闭索引校验。页面展示索引就绪状态和阻塞原因；只有启用菜品数量覆盖单次生成最大数量、引用分类与食材均有效、菜品名称与别名无冲突、食材名称与别名无冲突时才允许保存开启。索引校验已开启时，不允许保存会破坏就绪状态的数据修改。

## 10. 内容安全

### 10.1 图片资源

展示图片 Key 或 URL、来源、上传用户、绑定对象、审核状态和创建时间。管理员可定位失效资源，但不在列表中直接替换业务图片。

### 10.2 图片审核记录

- 查看阿里云同步审核请求、结果、风险标签、耗时和失败原因。
- 上传阶段违规、疑似风险、超时或接口失败均导致上传失败。
- AI 生成图片标记为 `not_required`，仍接受后续人工检查和违规处理。
- 管理端上传的官方菜品封面同样标记为 `not_required`，但来源明确为 `admin_upload`，不与用户上传混用。

### 10.3 图片审核配置

- 第一版供应商固定为阿里云图片审核接口，不与生成式 AI 供应商配置混用。
- 维护启用状态、AccessKey 安全引用、区域或 Endpoint、审核服务或场景、超时和重试；第一版安全引用固定为 `env://环境变量名`。
- AccessKey 只保存安全引用，列表、详情、测试结果和日志均不返回明文。
- 被引用环境变量保存 JSON 对象，必填 `accessKeyId` 和 `accessKeySecret`，临时凭据可选填 `securityToken`；Endpoint 必须是无路径、查询参数和用户信息的 HTTPS 地址。
- 展示固定适用场景、内部结果映射和失败关闭规则，管理员不能把违规、疑似、人工复核、超时或接口异常映射为通过。
- 支持编辑当前配置、连接测试、临时测试图片审核和操作审计；保存后立即生效。
- 连接和图片测试只使用当前已保存配置，不作为保存前置门槛；启用配置时服务端必须校验凭据和必填接入字段完整。连接测试通过获取临时 OSS 上传令牌验证鉴权和服务权限，图片测试按“临时 OSS 上传 → 同步图片审核 → 尽力清理临时对象”执行。
- AI 生成菜品图片固定不调用阿里云自动审核并记为 `not_required`，该规则不能在后台页面修改。
- 管理端官方菜品封面上传也固定不调用阿里云审核；图片审核启停只控制需要审核的用户上传场景。
- 超级管理员可修改；内容安全管理员默认只读；运营和客服默认不可见。

页面按钮、权限、停用影响和接口以 `order-food-admin-menu-page-review.md` 的 P14 及 `../admin/api.json` 为实施基线。

### 10.4 违规处理

处理动作：

- 关闭允许被发现。
- 软删除菜品。
- 严重违规时删除复制链。

处理前必须展示影响范围。严重违规复制链处理需二次确认，并异步执行、记录成功数和失败数。

推荐列表中的普通下线只影响当前推荐；从推荐发起违规处理时，推荐作为入口自动关联源菜品，一次确认后处理源头并同步下线该源头的全部在线推荐。一般违规不处理已有副本，严重违规才处理复制链。

### 10.5 通知

对已保存内容的违规处理结果写入站内通知。图片上传阶段即时拦截不生成通知中心记录。

## 12. AI 中心

### 12.1 平台策略

平台策略页包含：

- 平台总开关，初始化为关闭；开启后所有增强功能统一开放。
- 全局紧急停用，优先级高于平台总开关。
- 当前配置版本、修改管理员和修改时间。
- 正常用户数量和当前生效用户数量。
- 受策略影响的积分入口、积分流水、打卡奖励和偏好分析说明。

实际状态计算顺序为：全局紧急停用、平台总开关。管理端和小程序均不提供单用户或单项增强功能开关。平台总开关开启前，六项能力必须全部完成供应商、模型、提示词、积分和校验配置；开启后六项能力整体可用。

平台策略页同时维护小程序动态文案：

- 中性能力编码。
- 页面标题、按钮名称、说明。
- 积分费用和免费次数提示。
- 排序和配置版本。

编辑表单从当前配置回显；保存成功后立即更新小程序策略。正式环境默认文案不得依赖小程序本地兜底。

### 12.2 供应商管理

- 第一版固定支持千问（阿里云百炼）、DeepSeek 和 GPT（OpenAI）。
- 稳定供应商类型分别为 `bailian`、`deepseek`、`openai`；具体模型版本在模型管理页配置。
- 第一版不开放任意 `openai_compatible` 供应商；第三方中转或自建兼容网关以后单独评审。
- 配置名称、类型、基础地址、密钥引用、超时和备注；第一版密钥引用固定使用 `env://环境变量名`，被引用环境变量保存对应供应商 API Key。
- 密钥只保存安全引用，列表和详情均不返回明文。
- 提供连接测试，测试结果不得回显密钥。
- 新建供应商默认停用，新增和编辑表单都不提供启用开关；启停只能在列表使用独立操作并填写原因。
- 供应商只有在当前配置连接测试成功后才能启用；仍被启用模型或能力引用时不能停用。

### 12.3 模型管理

- 绑定供应商。
- 新增和编辑时从所选供应商实时返回的模型列表中下拉选择，不允许手工输入模型标识；已配置模型在新增时不可重复选择。
- 记录模型标识，并可同时标注文本、图片理解、图片生成中的一个或多个能力标签。
- 配置上下文长度、输入输出单价和备注。
- 已被启用能力引用的模型停用前必须提示影响范围。
- 新建模型默认停用，新增和编辑表单都不提供启用开关；启停只能在列表使用独立操作并填写原因。
- 模型只有在所属供应商已启用且配置完整时才能启用。

### 12.4 能力配置

每个 AI 能力独立维护运行参数，但不设置单项启停开关：

- 唯一主模型，不设置备用模型。
- 系统提示词和用户提示词模板；默认使用平台预设，超级管理员可编辑并直接保存。
- 提示词来源：平台默认或自定义。
- 当前能力允许和必需的模板变量。
- 固定积分消耗。
- 单用户日限额。
- 超时。
- 免费次数规则。
- 服务端固定结果校验规则，只读展示，不提供可编辑策略 JSON。
- 小程序中性能力编码。

小程序名称、按钮文案、说明和排序统一由平台策略维护，不在能力配置中重复编辑。

第一版能力包括：

| 能力 | 必需模型标签 |
| --- | --- |
| 菜品文本解析 | `text` |
| 菜谱长截图解析 | `vision` |
| 菜品封面生成 | `image_generation` |
| 打卡图片分析 | `vision` |
| 不知道吃什么 | `text` |
| 饭局备菜顺序 | `text` |

“不知道吃什么”必须先由 SQL 完成硬条件过滤、权限判断和推荐池召回；只有样本不足时才允许调用模型生成。每项能力的固定结果结构和业务校验由服务端强制执行，管理端只读展示且不能关闭。生成结果的标准菜名和食材词库匹配由“标准菜品索引”页的当前开关控制，基础结构校验始终执行。

平台总开关关闭时，所有增强能力接口均拒绝执行，后台仍保留当前有效配置和调用记录。平台总开关开启时，六项能力整体开放，不能只开放其中一项。某次调用失败或超时直接结束该次调用并进入退款流程，不自动切换模型，也不自动关闭总开关。

每项能力初始化时必须有一套可直接使用的平台默认提示词。管理员可以选择平台默认或自定义，编辑系统提示词和用户提示词模板，通过变量选择器插入系统允许的变量，预览变量替换结果并测试运行。测试用于诊断当前填写内容，不作为保存前置条件。

“恢复平台默认”只用默认正文覆盖当前表单，管理员点击“保存并立即生效”后更新当前配置。输出 JSON Schema 固定在服务端，管理端不能编辑。

模板变量由后端按能力固定提供，管理员不能新增变量；未知变量、缺失必需变量或模板无法渲染时禁止保存。权限、积分、限额、图片审核、SQL 候选过滤、结果结构校验、真实菜品校验和业务状态机在提示词之外强制执行，管理员不能通过编辑提示词改变。

测试运行使用管理员提供的测试数据，不扣用户积分、不写用户业务结果，但记录管理员、供应商、模型、当前配置版本、成本和请求 ID。

提示词正文查看、编辑和测试分别使用独立权限，默认只授予超级管理员。运营管理员只查看提示词来源和内容哈希摘要。测试只使用管理员提供的测试数据，不读取真实用户数据。

能力和提示词保存后立即替换当前有效配置，不提供草稿、发布、发布预览、历史版本、恢复或回滚页面。服务端仅保留内部单调递增版本号用于并发控制和缓存失效；审计记录保留操作人、时间、原因和变更摘要。

### 12.5 AI 调用记录

展示：

- 用户、能力、供应商和模型。
- 请求 ID、幂等号。
- 状态、耗时、token、图片数、积分消耗。
- 失败原因、退款状态和关联积分流水。

- 创建时间。

原始输入和模型输出属于敏感内容，只有授权角色可查看；手动清除后保留必要审计字段。

## 16. 核心后台工作流

### 16.1 可发现到推荐

1. 用户将可用菜品开启“允许被发现”。
2. 菜品进入后台可发现候选池。
3. 运营查看完整内容和作者信息。
4. 运营从候选菜行内创建已带入来源的推荐草稿，并一次确认发布。
5. 小程序推荐列表展示该内容。
6. 用户加入后生成个人未公开、不可再次发现的副本。
7. 源菜品关闭发现、编辑、删除或被违规处理时，在线推荐自动下线。

### 16.2 平台整体策略

1. 超级管理员修改平台默认状态或全局紧急停用。
2. 后台计算并展示受影响用户数量、积分入口和打卡奖励变化。
3. 管理员填写原因并二次确认。
4. 后端原子更新当前配置、递增并发版本号并使旧缓存失效。
5. 小程序下次登录、启动聚合或配置刷新时取得新版本。
6. 每次变更写管理员操作日志，包含变更前后值和追踪 ID。

不提供用户覆盖或单项能力开关。最终可调用条件为“未全局紧急停用、平台总开关开启、目标能力当前配置完整可用”。

### 16.3 AI 扣分与退款

1. 小程序携带请求幂等号发起能力调用。
2. 后端先校验平台总开关、紧急停用、能力配置完整性、限额、用户状态和积分。
3. 数据库事务锁定用户积分并写消耗流水。
4. 调用模型并记录成本。
5. 成功时保存结果并完成调用记录。
6. 失败或超时时立即尝试幂等退款；成功进入 `refunded`，写退款流水、恢复积分并发送站内通知。
7. 临时退款失败进入 `refund_pending`，小程序提示“处理失败，积分退还处理中”；后台任务持续重试至 `refunded`。
8. 管理端不提供手工退款按钮；后台可通过请求 ID 串联调用、消耗、待退款和最终退款。

### 16.4 违规处理

1. 管理员从候选池、推荐列表或资源记录进入违规处理。
2. 选择违规类型、处理动作并填写原因。
3. 系统预估对推荐、源菜品和复制链的影响。
4. 管理员二次确认高风险操作。
5. 后端事务或异步任务执行处理。
6. 写违规处理记录、管理员操作日志和用户通知。
7. 从推荐列表进入时提交入口推荐 ID，服务端校验推荐与源菜品关联一致；治理记录以源菜品为目标，并保留入口推荐 ID 追溯。
8. 用户源菜品处理写一条内容处理通知；官方源菜品处理不生成用户通知。严重违规复制链按实际受影响用户菜品逐条通知。

## 17. 数据与接口要求

- 后台接口统一使用 `{ code, data, msg }`。
- 分页统一使用 `{ page, pageSize, total, list }`。
- 业务状态使用稳定枚举，页面不从展示文案反推状态。
- 表格查询支持确定性排序。
- 列表响应只返回摘要，详情和敏感内容按需单独查询。
- 操作接口校验目标当前状态，状态不匹配返回 `40901`。
- 积分调整、推荐发布、违规处理和配置保存支持幂等保护。
- Swagger 注释必须和真实路由、权限、请求及响应一致。
- 管理端路由、DTO、权限和错误码逐条以 `../admin/api.json` 为准。
- 图片审核配置、“用户菜品”、“用户菜谱”及用户偏好画像查看是已确认范围；P02、P14、P25、P26 对应接口、DTO、权限和默认角色已经回写 `../admin/api.json`。
- “用户菜品”使用列表、私有详情和分页引用接口；“用户菜谱”使用列表与私有详情接口；用户偏好画像使用用户维度的独立只读接口。
- 私有菜品、私有菜谱和偏好画像不能复用普通 `user:read` 放大读取范围，必须使用独立权限并记录敏感详情访问。
- 菜谱违规处理需要稳定的 `recipe` 目标和 `soft_delete_recipe` 动作；处理结果保留关系审计，不删除关联菜品。
- 当前能力配置必须包含平台默认或自定义提示词模式、固定变量契约和内容哈希；提示词校验、渲染预览和测试运行使用独立接口。
- 提示词正文查看、编辑和测试分别使用独立权限，默认只授予超级管理员。
- 供应商类型首期冻结为 `bailian/deepseek/openai`；现有 `openai_compatible` 不作为 GPT 官方供应商类型直接对管理员开放。
- 对外错误码只在 `server/errors/error.go` 注册；管理端使用 `20000-29999`，不得复用小程序 `40000-49999`。

## 18. 验收标准

- 四类后台角色的菜单、按钮和 API 权限边界生效。
- 运营可以维护分类、标签、单位、官方菜品和推荐精选。
- 超管和内容安全管理员可按独立权限查询全部用户菜品和菜谱；运营、客服默认看不到这两个菜单。
- “用户菜品”覆盖私有、公开、草稿、可用和已软删除审计记录，不与可发现候选池混用。
- “用户菜谱”可以查看组成和失效引用，但管理员不能代用户编辑名称、备注、菜品或顺序。
- 可发现候选池没有多余的审核状态或审核队列。
- 用户推荐副本和 AI 推荐副本不能再次进入候选池。
- 用户禁用和恢复不会隐式删除其已有内容；禁用会按 `creator_disabled` 规则收口该用户发起的进行中饭局，已确认快照和采购清单保留只读。
- 新环境默认关闭标准菜品索引校验；索引未就绪时不能保存开启，开启后不能保存会破坏就绪状态的修改。
- 平台增强能力默认关闭，支持默认开启和全局紧急停用。
- 用户详情只读展示平台总开关或紧急停用形成的有效状态，不提供单用户例外。
- 平台总开关开启前六项能力配置全部就绪；开启后全部能力统一可用，不提供单项开关。
- 用户详情支持只读偏好画像，清楚区分用户主动设置和系统根据使用记录归纳的结果；默认仅超级管理员可查看。
- 打卡等证据先入证据记录再异步聚合画像；一次打卡不直接覆盖长期偏好。
- 增强能力或打卡图片分析关闭后，历史画像保留并显示暂停更新，不新增画像证据或聚合任务。
- 平台紧急停用覆盖所有用户；不存在单用户例外。
- 后台可以维护小程序中性能力编码、名称、按钮文案和说明，保存后立即按新配置生效。
- 用户增强能力关闭时，小程序积分及流水不可用，打卡不奖励积分且不触发偏好分析；历史积分数据保留。
- 积分调整、消耗和退款均可从流水追踪，且重试不重复记账。
- AI 能力可独立配置，失败调用能定位退款记录。
- 千问、DeepSeek、GPT 三类供应商可分别配置、测试并绑定模型，不出现未评审的任意供应商类型。
- 六项 AI 能力均有平台默认提示词，超级管理员可编辑、校验、测试并直接保存。
- 自定义提示词只能使用系统固定变量，平台硬规则、固定输出结构和结果校验不受提示词修改影响。
- 恢复平台默认只覆盖当前表单，保存后立即生效；提示词测试针对当前填写内容。
- 积分规则、生成校验策略、图片审核、平台整体能力、单项能力和提示词配置均不提供草稿、发布预览、发布、历史版本和回滚页面；保存直接替换当前有效配置，内部版本号只用于并发和缓存。
- 每项能力只有一个与模态兼容的主模型；模型失败不自动切换，供应商和模型新增后默认停用；固定订阅场景首次绑定微信模板后默认停用并通过独立状态操作启用。
- AI 调用退款支持 `refund_pending`，后台任务自动重试，不提供管理端手工退款。
- 官方菜品封面在编辑页上传或复用，管理端上传不走阿里云审核；编辑或删除官方菜品会在确认后自动下线在线推荐。
- 推荐只能从候选池或官方菜品行内创建，发布无预览和发布原因，手动下线原因必填。
- 微信订阅消息只保留饭局最终结果场景，关闭点餐、用户禁用和 AI 退积分不发送。
- 管理员可只读查看饭局、最终快照和采购清单，用于排查问题，不可越权修改。
- 违规处理具备原因、影响范围、二次确认、通知和审计记录。
- 图片上传审核失败与已保存内容的违规处理在后台记录中语义分离。
- 后台具备独立图片审核配置页，首期固定阿里云，可安全维护凭据引用、直接保存并测试当前配置。
- 私有菜品、私有菜谱详情和偏好画像访问均有独立读取权限及访问审计。
- 菜谱违规软删除不会删除菜谱内菜品，也不会修改历史饭局或采购快照。
- 所有列表具备分页、筛选、稳定排序、加载、空和错误状态。
- 小程序用户接口与后台管理接口使用独立认证边界。
- 关键页面和接口完成最小权限测试、状态冲突测试和幂等测试。
