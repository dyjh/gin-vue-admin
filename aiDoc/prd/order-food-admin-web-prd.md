## 2. 背景与定位

“来干饭”小程序已经完成前端页面、主要交互和 Mock 阶段，下一阶段需要建设真实后端与管理后台。后台管理端不是小程序功能的简单复制，而是平台运营、基础配置、内容治理、AI 成本控制和问题诊断的工作台。

后台的核心价值：

1. 让运营人员维护平台级分类、标签、单位、推荐内容和官方菜品。
2. 让管理员管理用户状态、积分和内容治理结果。
3. 让技术或运营人员配置 AI 供应商、模型、能力、费用和限额。
4. 让客服或管理员能够定位饭局、采购、通知和 AI 调用问题。
5. 对关键管理操作保留可追踪、可审计的记录。

后台不替普通用户维护其未公开菜品、个人菜谱、饭局点选结果或采购清单。

## 4. 产品目标

### 4.1 第一版目标

- 后台可以独立完成平台基础数据配置。
- 推荐内容从“允许被发现”的候选池中精选，不额外建立公开审核队列。
- 用户禁用、积分调整、内容处理和推荐上下线具备审计记录。
- AI 能力可以按业务场景独立启停、计费、限额和追踪调用。
- 管理员可以只读查看饭局关键链路，定位点餐、确认菜单和采购清单问题。
- 所有列表使用服务端分页、稳定排序和明确的空状态、异常状态。

### 4.2 非目标

第一版不包含：

- 后台代替用户创建或编辑未公开菜品、个人菜谱。
- 管理员直接修改参与者点选结果、最终份数或采购项。
- 重新开启已关闭饭局，或绕过业务状态机强制推进饭局。
- 多人实时协作采购、库存、价格、结算和仓储管理。
- 自由编辑生产提示词的低约束 Prompt IDE。
- 独立 BI 平台、数据仓库或微服务拆分。
- 作者主页、关注、评论、点赞和社交关系运营。

## 5. 用户角色与权限

### 5.1 超级管理员

- 拥有后台全部菜单和操作权限。
- 管理管理员角色、API 权限和菜单权限。
- 配置 AI 供应商密钥引用、模型和系统级开关。
- 可执行用户禁用、严重违规删除和复制链处理。

### 5.2 运营管理员

- 管理分类、标签、单位、官方菜品和推荐位。
- 从可发现候选池中精选或取消推荐。
- 查看用户、积分、饭局、采购和运营指标。
- 不可查看供应商密钥明文，不可管理系统管理员权限。

### 5.3 内容治理管理员

- 查看图片审核记录、可发现内容和治理记录。
- 关闭允许被发现、取消推荐、软删除违规内容。
- 对严重违规源菜品发起复制链处理。
- 每次处理必须填写原因和违规类型。

### 5.4 客服只读角色

- 只读查看用户、积分流水、饭局、采购、AI 调用和通知发送记录。
- 不可修改积分、用户状态、推荐状态或系统配置。

### 5.5 权限原则

- 菜单权限控制页面可见性。
- API 权限控制真实操作能力，不能只依赖前端隐藏按钮。
- 高风险操作增加按钮级权限和二次确认。
- 管理操作记录管理员、目标对象、变更前后摘要、原因、时间和请求追踪 ID。

## 7. 运营概览

### 7.1 页面目的

快速判断核心业务是否正常运行，优先展示可行动的信息，不建设复杂 BI 看板。

### 7.2 第一版指标

- 今日新增用户、活跃用户。
- 新用户首次创建菜品率。
- 可用菜品数、允许被发现菜品数、推荐中菜品数。
- 今日创建饭局数、加入人数、确认菜单数、采购清单生成数。
- 今日打卡数、获得积分、消耗积分、退款积分。
- AI 调用成功率、失败率、平均耗时、当日估算成本。
- 当前平台默认能力状态、紧急停用状态、用户覆盖数量。
- 未处理治理记录数、图片审核失败数。
- 订阅消息发送失败数。

### 7.3 交互规则

- 默认查看今日，可切换近 7 天和近 30 天。
- 指标卡可跳转到对应筛选后的列表。
- 数据刷新失败时保留上次成功数据并显示更新时间和错误提示。
- 指标只用于运营判断，不作为财务结算依据。

## 8. 用户与积分

### 8.1 小程序用户列表

筛选条件：

- 用户 ID、昵称。
- 正常、已禁用。
- 增强能力有效状态、用户覆盖状态。
- 注册时间、最近登录时间。
- 积分区间。

列表字段：

- 用户公开 ID。
- 头像、昵称。
- 当前积分。
- 增强能力有效状态及来源：平台默认或用户覆盖。
- 累计打卡天数。
- 菜品数、饭局数。
- 状态、注册时间、最近登录时间。

操作：

- 查看详情。
- 禁用或恢复用户。
- 设置增强能力为跟随平台、开启或关闭。
- 进入积分调整。

禁用用户时必须填写原因。禁用只阻止用户登录和使用核心功能，不自动删除或下架既有内容。

### 8.2 用户详情

展示：

- 基础资料和账号状态。
- 脱敏微信身份及最后登录时间。
- 增强能力有效状态、计算来源和用户覆盖状态。
- 当前积分与最近积分流水。
- 菜品、菜谱、饭局、打卡数量摘要。
- 最近 AI 调用和退款记录。
- 最近通知。
- 管理操作记录。

后台不在此页直接编辑用户私有菜品内容。

修改用户能力覆盖状态时必须填写原因，并展示修改后的积分入口、打卡奖励和偏好分析是否可用。平台处于紧急停用时，用户即使设置为开启，有效状态仍为关闭。

### 8.3 积分流水

- 支持按用户、类型、业务场景、关联对象、时间和请求幂等号查询。
- 类型统一为获得、消耗、退款、人工调整。
- 消耗与退款通过关联流水 ID 建立关系。
- 流水不可编辑或物理删除。

### 8.4 人工积分调整

- 输入用户、调整方向、积分数和原因。
- 调整后写入流水并更新用户当前积分。
- 扣减后余额不得小于 0。
- 提交前展示调整前后余额。
- 同一次提交使用幂等键，防止重复点击产生多条流水。

## 9. 菜品运营

### 9.1 分类、标签和单位

共同能力：

- 新增、编辑、启用、停用、排序。
- 名称唯一校验。
- 已被业务数据引用时不允许物理删除，只能停用。
- 停用项不再出现在新建表单中，历史数据继续展示原值。

分类用于菜品侧栏和筛选；标签最多由用户选择 3 个；单位用于配料数量表达。

### 9.2 可发现候选池

候选来源仅包括：

- 状态为可用。
- 用户主动开启“允许被发现”。
- 未被治理删除。
- 不是平台推荐副本或 AI 推荐副本。

列表展示：

- 封面、菜名、分类、标签、作者。
- 允许被发现开启时间。
- 被点人数、被复制次数。
- 是否已被精选、当前推荐位置。

操作：

- 查看完整只读详情。
- 精选到推荐。
- 因治理原因关闭允许被发现。
- 对违规内容执行软删除。

本页不提供“审核通过/驳回”。管理员精选到推荐本身就是内容把关行为。

### 9.3 推荐精选

推荐记录具有独立状态：

- `draft`：已选中但未发布。
- `published`：正在小程序推荐位展示。
- `offline`：已下线。

支持：

- 设置推荐位和排序。
- 预览推荐详情。
- 发布、下线和重新排序。
- 查看来源作者或“来干饭官方”来源。

用户关闭允许被发现、编辑源菜品、删除源菜品或被治理时，相关在线推荐自动下线。

### 9.4 官方菜品

- 由平台直接发布，作者展示为“来干饭官方”。
- 必须有封面、分类、基础份量、配料和做法步骤。
- 可作为推荐内容发布。
- 用户加入菜品库后生成个人副本。
- 个人副本默认未公开，允许编辑，永久不能再次开启允许被发现。

官方菜品不是管理员代用户创建的私有菜品。

## 10. 内容治理

### 10.1 图片资源

展示图片 Key 或 URL、来源、上传用户、绑定对象、审核状态和创建时间。管理员可定位失效资源，但不在列表中直接替换业务图片。

### 10.2 图片审核记录

- 查看阿里云同步审核请求、结果、风险标签、耗时和失败原因。
- 上传阶段违规、疑似风险、超时或接口失败均导致上传失败。
- AI 生成图片标记为 `not_required`，仍可进入后续人工治理。

### 10.3 内容处理

处理动作：

- 关闭允许被发现。
- 取消推荐。
- 软删除菜品。
- 禁用用户。
- 严重违规时删除复制链。

处理前必须展示影响范围。严重违规复制链处理需二次确认，并异步执行、记录成功数和失败数。

普通取消推荐、普通下架来源或用户自删不级联删除已有副本。

### 10.4 通知

对已保存内容的治理结果写入站内通知。图片上传阶段即时拦截不生成通知中心记录。

## 11. 饭局与采购诊断

### 11.1 饭局列表

筛选：

- 饭局 ID、名称、创建者。
- 收集中、已关闭、已确认、已取消。
- 创建时间、截止时间、关闭原因。

详情展示：

- 创建者、点餐码摘要、参与人数。
- 候选菜、想吃人数和最终份数。
- 状态流转时间线。
- 最终菜品快照。
- 采购清单生成状态。

第一版默认只读，不允许后台修改票数、份数、截止时间或状态。

### 11.2 采购清单

展示：

- 来源饭局。
- 待购买和已购买数量。
- 清单项及来源菜品。
- 只读分享令牌状态和过期时间。

后台不替创建者勾选、编辑、新增或删除采购项。

## 12. AI 中心

### 12.1 平台策略

平台策略页包含：

- 平台默认状态，初始化为关闭。
- 全局紧急停用，优先级高于平台默认和所有用户覆盖。
- 当前配置版本、发布状态、修改管理员和修改时间。
- 跟随平台、明确开启、明确关闭的用户数量。
- 受策略影响的积分入口、积分流水、打卡奖励和偏好分析说明。

用户覆盖为三态：

- 跟随平台。
- 开启。
- 关闭。

实际状态计算顺序为：全局紧急停用、用户覆盖、平台默认。平台策略和用户覆盖都必须由后端计算，后台页面只展示计算结果。

平台策略页同时维护小程序动态文案：

- 中性能力编码。
- 页面标题、按钮名称、说明。
- 积分费用和免费次数提示。
- 排序、启用状态和配置版本。

未发布草稿不影响小程序。发布前展示影响用户数量并要求二次确认。正式环境默认文案不得依赖小程序本地兜底。

### 12.2 供应商管理

- 支持通义千问/阿里云百炼、DeepSeek 和 OpenAI 兼容接口。
- 配置名称、类型、基础地址、密钥引用、超时、重试和启用状态。
- 密钥只保存安全引用，列表和详情均不返回明文。
- 提供连接测试，测试结果不得回显密钥。

### 12.3 模型管理

- 绑定供应商。
- 记录模型标识、支持文本/图片理解/图片生成能力。
- 配置上下文长度、输入输出单价、启用状态和备注。
- 已被启用能力引用的模型停用前必须提示影响范围。

### 12.4 能力配置

每个 AI 能力独立配置：

- 启用状态。
- 主模型、备用模型。
- 固定积分消耗。
- 单用户日限额。
- 超时和重试。
- 免费次数规则。
- 结果校验策略。
- 小程序中性能力编码。
- 小程序名称、按钮文案、说明和排序。

第一版能力包括：

- 菜品文本解析。
- 菜谱长截图解析。
- 菜品封面生成。
- 打卡图片分析。
- 不知道吃什么。
- 饭局备菜顺序。

“不知道吃什么”必须先由 SQL 完成硬条件过滤、权限判断和推荐池召回；只有样本不足时才允许调用 AI。AI 结果必须是现实存在的菜品、常见材料和可验证做法。

独立能力开关只在用户增强能力有效状态为开启时生效。有效状态关闭时，所有独立能力接口均拒绝执行，后台仍保留历史配置和调用记录。

### 12.5 AI 调用记录

展示：

- 用户、能力、供应商和模型。
- 请求 ID、幂等号。
- 状态、耗时、token、图片数、积分消耗。
- 失败原因、退款状态和关联积分流水。
- 创建时间。

原始输入和模型输出属于敏感内容，只有授权角色可查看；手动清除后保留必要审计字段。

## 13. 通知与配置

### 13.1 站内通知

- 按用户、类型、已读状态、目标对象和时间查询。
- 默认稳定按 `createdAt DESC, id DESC` 排序。
- 管理员可查看投递结果，不直接修改用户已读状态。

### 13.2 微信订阅消息

- 维护模板 ID、用途、启用状态和字段映射。
- 发送前校验用户是否授权对应模板。
- 发送失败不影响站内通知。
- 记录微信返回码、错误摘要和重试情况。

## 14. 通用交互与状态

- 列表默认每页 20 条，允许切换 20、50、100。
- 服务端分页，筛选变化后回到第 1 页。
- 表格主键稳定，禁止使用数组索引作为行标识。
- 空状态说明“为什么为空”和可执行的下一步。
- 加载失败提供重试，不把空数组伪装成成功。
- 写操作提交期间禁用重复提交。
- 状态冲突返回最新状态并提示刷新。
- 高风险按钮使用语义明确的图标和文案，不使用含义模糊的删除图标代替关闭。
- 日期时间以用户本地时区展示，接口统一使用 ISO 8601。

## 15. 审计与安全

- 后台沿用 GVA 管理员 JWT、角色、菜单、按钮和 API 权限体系。
- 小程序用户令牌不能调用后台管理接口。
- 管理员令牌不能伪装成小程序用户执行个人业务操作。
- 所有写操作记录请求追踪 ID。
- 禁用、积分调整、治理、推荐发布、平台能力策略、用户能力覆盖和 AI 配置变更必须写操作日志。
- 敏感配置、用户原始 AI 输入和图片审核信息遵循最小权限。
- 导出能力第一版仅在确有运营需求的列表开放，并受独立权限控制。

## 16. 核心后台工作流

### 16.1 可发现到推荐

1. 用户将可用菜品开启“允许被发现”。
2. 菜品进入后台可发现候选池。
3. 运营查看完整内容和作者信息。
4. 运营创建推荐精选记录并发布。
5. 小程序推荐列表展示该内容。
6. 用户加入后生成个人未公开、不可再次发现的副本。
7. 源菜品关闭发现、编辑、删除或被治理时，在线推荐自动下线。

### 16.2 平台策略与用户覆盖

1. 超级管理员修改平台默认状态或全局紧急停用。
2. 后台计算并展示受影响用户数量、积分入口和打卡奖励变化。
3. 管理员填写原因并二次确认。
4. 后端保存新配置版本并使旧缓存失效。
5. 小程序下次登录、启动聚合或配置刷新时取得新版本。
6. 单个用户覆盖在用户详情设置为跟随平台、开启或关闭。
7. 每次变更写管理员操作日志，包含变更前后值和追踪 ID。

### 16.3 AI 扣分与退款

1. 小程序携带请求幂等号发起能力调用。
2. 后端先校验平台策略、用户覆盖、独立能力、限额、用户状态和积分。
3. 数据库事务锁定用户积分并写消耗流水。
4. 调用模型并记录成本。
5. 成功时保存结果并完成调用记录。
6. 失败或超时时幂等写退款流水、恢复积分并发送站内通知。
7. 后台可通过请求 ID 串联调用、消耗和退款。

### 16.4 内容治理

1. 管理员从候选池、推荐列表或资源记录进入治理。
2. 选择违规类型、处理动作并填写原因。
3. 系统预估对推荐、源菜品和复制链的影响。
4. 管理员二次确认高风险操作。
5. 后端事务或异步任务执行处理。
6. 写治理记录、管理员操作日志和用户通知。

## 17. 数据与接口要求

- 后台接口统一使用 `{ code, data, msg }`。
- 分页统一使用 `{ page, pageSize, total, list }`。
- 业务状态使用稳定枚举，页面不从展示文案反推状态。
- 表格查询支持确定性排序。
- 列表响应只返回摘要，详情和敏感内容按需单独查询。
- 操作接口校验目标当前状态，状态不匹配返回 `40901`。
- 积分调整、推荐发布、治理和配置保存支持幂等保护。
- Swagger 注释必须和真实路由、权限、请求及响应一致。

## 18. 验收标准

- 四类后台角色的菜单、按钮和 API 权限边界生效。
- 运营可以维护分类、标签、单位、官方菜品和推荐精选。
- 可发现候选池没有多余的审核状态或审核队列。
- 用户推荐副本和 AI 推荐副本不能再次进入候选池。
- 用户禁用和恢复不会隐式删除其已有内容。
- 平台增强能力默认关闭，支持默认开启和全局紧急停用。
- 用户详情支持“跟随平台、开启、关闭”三态覆盖，并正确展示有效状态及来源。
- 平台紧急停用覆盖所有用户；用户覆盖不能绕过紧急停用。
- 后台可以维护小程序中性能力编码、名称、按钮文案和说明，配置发布后按版本生效。
- 用户增强能力关闭时，小程序积分及流水不可用，打卡不奖励积分且不触发偏好分析；历史积分数据保留。
- 积分调整、消耗和退款均可从流水追踪，且重试不重复记账。
- AI 能力可独立配置，失败调用能定位退款记录。
- 管理员可只读诊断饭局、最终快照和采购清单，不可越权修改。
- 治理操作具备原因、影响范围、二次确认、通知和审计记录。
- 图片上传审核失败与已保存内容治理在后台记录中语义分离。
- 所有列表具备分页、筛选、稳定排序、加载、空和错误状态。
- 小程序用户接口与后台管理接口使用独立认证边界。
- 关键页面和接口完成最小权限测试、状态冲突测试和幂等测试。

## 19. 实施顺序

1. 建立 `orderfood` 后端业务包、权限与菜单骨架。
2. 完成分类、标签、单位等稳定 CRUD。
3. 完成微信用户、平台能力策略、用户覆盖、积分、菜品候选池和推荐精选。
4. 完成图片资源、审核记录和内容治理。
5. 完成 AI 供应商、模型、能力、动态文案和调用记录。
6. 完成饭局、采购和通知只读诊断页面。
7. 完成运营概览、权限收口和端到端验收。

实现必须与小程序真实接口按领域同步推进，避免先做出一套无法解释小程序状态的孤立后台。
