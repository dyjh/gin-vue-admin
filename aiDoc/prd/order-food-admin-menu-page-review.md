### 2.1 “28 个页面”的口径

28 个页面指本实施基线中的 28 个菜单叶子页面；“积分规则”“图片审核配置”“用户菜品”“用户菜谱”“标准菜品索引”“微信配置”及用户详情“偏好画像”所需接口、DTO 和权限已经回写实现。页面数量不包括：

- 详情抽屉。
- 新增或编辑隐藏路由。
- 影响预览和高风险确认弹窗。
- 操作审计等内嵌标签页。
- 小程序用户详情中的“偏好画像”标签页。
- 从用户列表或积分流水页打开的积分调整弹框。

页面编号是评审稿中的稳定标识，不代表菜单展示顺序。新增的 P25、P26、P27、P28、P29 不重排既有 P01—P24，避免接口、评审意见和实施任务引用失效。

除已确认纳入的四个新增页面外，产品审查发现的其他新增范围不会直接塞入菜单；先在第 14 节审核其必要性，再决定是否扩展页面数量。

### 3.2 菜单排序原则

1. 先日常运营，后基础配置。
2. 先问题结果，后技术参数。
3. 同一业务闭环尽量相邻，例如可发现候选池、推荐精选、官方菜品。
4. 只读查看与可写运营分区，降低管理员误以为可以代用户操作的概率。
5. GVA 自带的系统管理、角色、菜单和 API 权限不放入“来干饭”业务菜单。

## 4. 页面和按钮通用规则

### 4.1 页面标准结构

列表页面从上到下统一为：

1. 页面标题、用途说明和主操作按钮。
2. 筛选区：默认展示常用条件，低频条件进入“更多筛选”。
3. 已生效筛选标签和“清空筛选”。
4. 数据表格或卡片区。
5. 分页区：默认 20 条，可切换 20、50、100 条。
6. 详情抽屉、编辑抽屉或确认弹窗。

筛选项变化后不自动请求；点击“查询”后回到第 1 页。“重置”恢复默认筛选并立即重新查询。

### 4.2 通用按钮语义

| 按钮 | 使用规则 |
| --- | --- |
| 查询 | 按当前筛选条件重新加载，回到第 1 页 |
| 重置 | 清除筛选、恢复默认排序并重新加载 |
| 刷新 | 保留当前筛选和页码，获取最新数据 |
| 查看详情 | 打开只读抽屉或隐藏子路由，不改变数据 |
| 新增 | 打开空白表单；提交成功后回到列表并定位新记录 |
| 编辑 | 打开当前版本数据；保存时携带版本号 |
| 启用/停用 | 使用明确文案，不用只有图标的开关直接提交 |
| 保存草稿 | 仅用于推荐、官方菜品等具有内容生命周期的业务对象 |
| 影响预览 | 仅用于积分调整、违规处理等高风险业务动作，不用于普通配置保存 |
| 确认发布 | 仅用于推荐内容发布，不用于配置模块 |
| 删除 | 仅用于契约定义的删除；“下线”“停用”“清除敏感内容”不得统称删除 |
| 取消 | 关闭弹窗或放弃未提交表单，不请求写接口 |

### 4.3 权限与状态

- 没有页面读取权限：菜单和路由均不可见。
- 有页面权限但没有按钮权限：隐藏对应按钮，接口仍由后端鉴权。
- 有按钮权限但当前状态不允许：按钮禁用，并通过提示说明前置条件。
- 表格中的操作列固定在右侧；超过 3 个低频动作时收入“更多”菜单。
- 操作成功后刷新当前记录；发生版本冲突时保留用户输入并提示加载最新版本。
- 所有写按钮在提交中显示加载状态并禁止重复点击。

### 4.4 详情承载方式

| 类型 | 承载方式 | 示例 |
| --- | --- | --- |
| 简短只读信息 | 右侧抽屉 | 图片资源、消息、审核记录 |
| 多标签关联信息 | 宽抽屉或隐藏详情路由 | 用户、饭局、采购清单、违规处理记录 |
| 长表单 | 隐藏编辑路由 | 官方菜品编辑 |
| 配置工作区 | 当前页面分栏 | 平台策略、能力配置 |
| 高风险确认 | 按业务风险选一次或两步弹窗 | 推荐发布一次确认；积分调整和违规处理两步确认 |

详情路由不显示为菜单项，但必须支持刷新和复制链接后再次打开。

### 4.5 风险等级

| 等级 | 示例 | 交互要求 |
| --- | --- | --- |
| L0 只读 | 查询、查看详情、复制 ID | 无确认 |
| L1 可逆配置 | 编辑、启用、停用 | 展示变化；停用需填写原因 |
| L2 业务高风险 | 积分调整、用户禁用、推荐下线 | 展示影响、原因必填、二次确认；推荐发布按 R37 一次确认且不填原因 |
| L3 扩散或敏感操作 | 严重违规复制链处理、清除 AI 敏感内容 | 影响预览、醒目警告、原因必填、输入确认词、异步结果追踪 |

- 显示数据生成时间；刷新失败时保留上次成功数据。

**按钮和功能**

| 按钮/入口 | 位置 | 功能 | 条件 |
| --- | --- | --- | --- |
| 今日 / 近 7 天 / 近 30 天 | 页头 | 切换统计范围并刷新全部指标 | 始终可用 |
| 刷新 | 页头 | 保留当前范围重新获取数据 | 始终可用 |
| 查看明细 | 指标卡 | 跳到对应列表并带入时间和状态筛选 | 拥有目标页面权限 |
| 去处理 | 异常提醒 | 跳到违规处理、AI 调用或消息记录的异常筛选结果 | 拥有目标页面权限 |

- 不提供导出。
- 不允许直接从指标卡执行违规处理或配置变更。
- 不把估算成本作为正式结算金额。

## 6. 用户与积分

### P02 小程序用户

**页面目标**

检索用户、判断账号与增强能力状态、进入用户内容、积分和调用记录，并在严格授权下查看由打卡等证据聚合形成的偏好画像。

**筛选和列表**

- 筛选：用户 ID 或昵称、账号状态、增强能力有效状态、注册时间、最近登录时间、积分区间。
- 列表：公开 ID、头像昵称、积分、增强能力状态及来源、打卡天数、菜品数、饭局数、账号状态、注册与最近登录时间。
- 详情标签：概览、偏好画像、积分流水、AI 调用、站内通知、操作记录；无相应读取权限的标签隐藏。
- 概览中的“菜品数”“菜谱数”分别提供跳转入口，带当前用户 ID 打开“用户菜品”“用户菜谱”。

**按钮和功能**

| 按钮 | 位置 | 功能与结果 | 显示或启用条件 |
| --- | --- | --- | --- |
| 查询 | 筛选区 | 按条件查询用户 | 页面可读 |
| 重置 | 筛选区 | 恢复默认筛选 | 页面可读 |
| 查看详情 | 行操作 | 打开用户详情和关联记录标签 | `user:read` |
| 查看偏好画像 | 详情标签 | 查看聚合画像、更新状态和打卡贡献摘要 | `user:preference:read` |
| 查看全部菜品 | 概览 | 跳转用户菜品并锁定当前用户筛选 | `user-dish:read` |
| 查看全部菜谱 | 概览 | 跳转用户菜谱并锁定当前用户筛选 | `user-recipe:read` |
| 调整积分 | 行操作、详情页 | 打开积分调整弹框并预填用户 | `points:adjust` |
| 禁用用户 | 行操作、详情页 | 填写原因后禁用登录和核心接口；同步取消该用户发起的进行中饭局，已确认快照和采购清单保留只读 | `user:disable` 且用户正常 |
| 恢复用户 | 行操作、详情页 | 填写原因后恢复账号，不自动恢复此前已处理的违规内容 | `user:disable` 且用户已禁用 |

**关键交互**

- 用户能力状态只读展示平台总开关或全局紧急停用的计算结果，不提供单用户例外设置。
- 平台总开关开启即开放全部六项能力；保存开启前必须保证六项能力配置全部就绪。
- 禁用操作为 L2；确认页明确说明“不删除、不下线用户已有内容”，并展示将取消的进行中饭局、受影响参与者和将保留的已确认快照、采购清单数量。
- 禁用事务将该用户发起的 `collecting/closed/confirmed` 饭局统一转为 `cancelled`，取消原因为 `creator_disabled`；已确认数据保留只读，参与者收到站内通知。
- 后台不编辑用户头像、昵称、私有菜品或私有菜谱。

**偏好画像标签**

画像页签展示的是聚合后的长期结果，不把一次打卡识别结果直接称为用户偏好。

- 概览：画像状态、累计打卡天数、最近更新时间、当前是否继续更新。
- 画像内容：常用菜品标签、常点菜品标签、常用配料、口味偏好摘要、忌口或偏好备注摘要。
- 打卡贡献：已进入聚合的打卡证据数、待聚合数、最近一次打卡证据时间；只展示数量和结构化摘要，不展示打卡原图。
- 其他来源摘要：采用推荐、保存菜品、点菜、换一道、先不考虑、用户明确设置的证据数量。
- 用户主动填写的过敏、忌口和饮食限制使用“用户设置”标识；系统归纳出的口味和配料偏好使用“根据使用记录归纳”标识，两者不得混为一类。
- 能力关闭或打卡图片分析停用时保留历史画像，状态显示“当前已暂停更新”，并展示暂停原因。
- 尚未形成画像时显示空状态：“暂无可用画像。符合条件的打卡和其他使用记录会异步参与归纳。”
- 最近一次聚合失败时只展示失败时间、稳定错误摘要和请求 ID，不能展示模型思考过程、完整提示词或内部敏感信息。
- 接口状态拆为 `hasProfile` 与 `updateState`，其中 `updateState` 冻结为 `active`、`pending`、`paused`、`failed`；历史画像存在但最近更新失败时继续展示旧画像，同时单独提示失败。

首版只读，不提供编辑画像、手动重算、删除证据、删除画像或查看完整证据明细。`user:read` 不自动包含画像读取能力；`user:preference:read` 默认只授予超级管理员，每次打开页签记录管理员、用户、时间和请求 ID。

## 7. 菜品运营

### P28 标准菜品索引

**页面目标**

维护“生成建议”所需的标准菜名、菜系、分类和食材关系，并控制生成结果是否必须经过本页索引与词库匹配。该页面只提供校验依据，不保存完整菜谱，不参与可发现候选池、平台推荐或官方菜品展示。

**页面内容**

- 校验策略卡片：当前开关、配置版本、更新人、更新时间、修改原因和固定额外重试次数。
- 菜品索引：标准菜名、别名、菜系、平台分类、允许食材、必需食材、来源说明、启用状态和版本。
- 食材词库：标准食材名、别名、启用状态和版本。
- 数量概览：菜品索引、食材词库各自的总数与启用数。

**按钮和功能**

| 按钮 | 功能与结果 | 启用条件 |
| --- | --- | --- |
| 保存策略并立即生效 | 填写原因并保存“使用索引和词库校验生成结果”开关 | `suggestion-catalog:update` |
| 新增 / 编辑菜品索引 | 维护标准菜名、别名、菜系、分类、来源和食材范围 | `suggestion-catalog:update` |
| 新增 / 编辑标准食材 | 维护标准名、别名和启用状态 | `suggestion-catalog:update` |
| 查询 / 重置 / 分页 | 查询菜品索引或食材词库 | `suggestion-catalog:read` |

**关键交互**

- 开关关闭时，只跳过标准菜品索引和食材词库匹配；字段结构、分类、标签、单位、配料与步骤一致性仍然强制校验。
- 新环境默认关闭索引校验。只有以下条件全部满足时才允许保存开启：启用菜品数不少于单次生成可能要求的最大菜品数；启用菜品引用的分类和食材均启用；菜名与别名在菜品索引内归一化后无冲突；食材名与别名在食材词库内归一化后无冲突。
- 页面展示“索引已就绪 / 索引未就绪”和逐项阻塞原因；保存关闭不受就绪条件限制。
- 索引校验已开启时，不允许保存会破坏就绪状态的菜品、食材或分类修改；错误提示列出受影响引用，管理员需要先保存关闭索引校验。
- 开关开启时，首次生成、供应商调用或校验失败后，在同一笔使用中固定额外尝试 1 次。两次都失败才将使用标记为失败，退还已扣积分，且不占用免费次数。
- 开关关闭时只尝试 1 次；失败后同样退还已扣积分且不占用免费次数。
- 重试次数固定为 1，不提供管理员编辑入口；两次尝试共用同一个请求、使用记录和计费过程，不得重复扣分。
- 停用索引或食材后，仅影响后续生成校验，不追溯修改已返回的建议快照和用户已经保存的个人菜品。

### P25 用户菜品

**页面目标**

跨用户查询个人菜品，核对内容、来源、引用位置和删除原因，并在授权时处理违规内容。它覆盖草稿、可用、公开、私有和已软删除的审计记录；“可发现候选池”仍只负责用户主动允许被发现的可用菜品及精选推荐。

**范围边界**

- 包含用户手工创建、复制官方菜品、复制推荐菜品、保存增强建议等形成的个人菜品。
- 不包含平台维护的官方菜品本体；用户复制出的个人副本应包含在内。
- “全部”表示所有用户和所有业务状态，默认先查未删除内容，可通过筛选查看已软删除记录；已物理清除且没有业务记录的数据不在范围内。

**筛选和列表**

- 筛选：菜品 ID 或菜名、用户 ID 或昵称、草稿或可用状态、正常或已删除、是否允许被发现、来源类型、是否来源锁定、分类、标签、图片审核状态、创建时间、更新时间、删除时间。
- 列表：封面、菜品 ID、菜名、所属用户、分类标签、状态、发现状态、来源、菜谱引用数、未确认饭局引用数、图片审核状态、删除状态、创建时间和更新时间。
- 详情标签：
  - 内容：封面、简介、份量、配料和步骤。
  - 归属与来源：所属用户、来源类型、源菜品、根菜品、来源锁和复制链摘要。
  - 使用位置：所在菜谱、未确认饭局引用、已确认饭局和采购历史快照计数。
  - 状态与记录：发现状态、推荐状态、图片审核摘要、删除信息、违规处理记录和管理员操作记录。

**按钮和功能**

| 按钮 | 位置 | 功能与结果 | 条件 |
| --- | --- | --- | --- |
| 查询 / 重置 | 筛选区 | 查询或清空筛选 | `user-dish:read` |
| 查看详情 | 行操作 | 打开完整菜品详情 | `user-dish:private-read` |
| 查看用户 | 行操作、详情页 | 打开所属用户详情 | `user:read` |
| 查看来源 / 复制链 | 详情页 | 查看源菜品、根菜品和复制关系摘要 | `user-dish:private-read` |
| 查看引用 | 详情页 | 查看菜谱和未确认饭局引用 | `user-dish:private-read` |
| 转到候选池 / 查看推荐 | 行操作 | 按菜品 ID 跳到候选或推荐记录 | 目标存在且拥有目标页面权限 |
| 违规处理 | 行操作、详情页 | 预览后关闭发现或软删除菜品，并自动下线该源头的全部在线推荐 | `governance:execute` |
| 严重违规复制链处理 | 违规处理弹窗 | 预览影响后处理源菜品及复制链 | `governance:cascade` 且满足严重违规条件 |

**关键交互**

- 私有、草稿和已删除菜品的封面、简介、配料、步骤属于受限内容；只有 `user-dish:private-read` 才返回，打开完整详情必须记录访问审计。
- 软删除菜品后，不再用于新菜谱和新饭局；从未确认饭局中移除；已经确认的饭局和采购清单只保留文字快照，不回写历史内容。
- 禁用用户必须跳到用户详情单独执行，不能作为菜品处理的隐藏附带动作。
- 页面不提供新增、编辑、替用户切换草稿或可用状态、替用户开启发现、普通删除、恢复、批量处理或导出。

### P26 用户菜谱

**页面目标**

跨用户查询个人菜谱、备注和菜品组成，排查失效引用或违规内容。菜谱是用户组织自己菜品的私有容器，不进入推荐池，管理员不能代用户维护其内容。

**筛选和列表**

- 筛选：菜谱 ID 或名称、用户 ID 或昵称、包含的菜品 ID、菜品数量区间、正常或已删除、空菜谱、是否含失效菜品、创建时间和更新时间。
- 默认不提供备注全文模糊搜索，避免把用户私密自然语言建立为普通运营检索条件。
- 列表：派生封面、菜谱 ID、菜谱名称、所属用户、菜品数、失效菜品数、是否有备注、状态、创建时间和更新时间；列表不展示备注全文。
- 详情：名称和备注、按用户顺序排列的菜品清单、每道菜当前状态与来源、添加时间、关系审计、删除信息和管理员操作记录。封面取第一道仍可用菜品的封面，没有可用菜品时显示空占位。

**按钮和功能**

| 按钮 | 位置 | 功能与结果 | 条件 |
| --- | --- | --- | --- |
| 查询 / 重置 | 筛选区 | 查询或清空筛选 | `user-recipe:read` |
| 查看详情 | 行操作 | 打开菜谱备注和有序菜品清单 | `user-recipe:private-read` |
| 查看用户 | 行操作、详情页 | 打开所属用户详情 | `user:read` |
| 查看所含菜品 | 详情页 | 跳转用户菜品并带入菜谱或菜品筛选 | `user-dish:read` |
| 违规处理 | 行操作、详情页 | 预览后软删除菜谱并通知用户 | `governance:execute`；需扩展 `recipe` 目标 |

**关键交互**

- 菜谱软删除只改变菜谱本身，保留关系审计，不删除其中菜品，也不改变历史饭局和采购清单快照。
- 如果违规对象是菜谱中的某道菜，必须转到菜品详情处理，不能用删除菜谱代替菜品处理。
- 私有菜谱备注和菜品清单只有 `user-recipe:private-read` 才返回，打开完整详情必须记录访问审计。
- 页面不提供改名、编辑备注、增加或移除菜品、调整顺序、恢复、批量处理或导出。

### P06 推荐精选

**页面目标**

管理小程序推荐内容从草稿、发布到下线的完整生命周期。

**筛选和列表**

- 列表：封面、菜名、来源、推荐位、排序、状态、发布时间、下线原因、来源有效性。

**按钮和功能**

| 按钮 | 位置 | 功能与结果 | 状态条件 |
| --- | --- | --- | --- |
| 查看详情 | 行操作 | 查看推荐内容、来源和状态 | 有读取权限 |
| 编辑 | 行操作 | 修改推荐位、排序和展示说明 | 草稿、已发布或已下线；来源始终不可更换 |
| 发布 / 重新发布 | 行操作 | 一次确认后发布，服务端实时校验来源、封面、容量和版本 | 草稿或已下线且 `recommendation:publish` |

**关键交互**

- P06 页头不提供“新建推荐”；草稿只能从 P05 或 P07 行内入口创建并自动带入来源。
- 发布和重新发布不生成预览令牌、不填写发布原因；容量和版本等条件在发布事务中实时校验。
- 下线按钮不能命名为“删除”。
- 手动下线原因必填；来源关闭发现、被编辑、删除或被违规处理时自动下线并展示固定系统原因。

- 一般违规可关闭用户源菜品的发现或软删除源菜品；官方源菜品一般违规直接软删除。严重违规处理源头及全部用户复制菜品。
- 源头处理同步下线该源头关联的所有在线推荐，而不只是当前入口推荐；官方源菜品处理不生成用户通知。
- 第一版不支持批量发布或批量下线。

## 12. 跨页面核心工作流

### 12.1 用户投诉积分异常

```text
小程序用户
→ 用户详情
→ 积分流水
→ 关联 AI 调用或退款记录
→ 确认确需人工处理
→ 积分调整预览
→ 确认调整
→ 返回新积分流水
```

### 12.2 用户菜品精选到推荐

```text
可发现候选池
→ 查看菜品详情
→ 精选到推荐
→ 生成推荐草稿
→ 一次确认发布
→ 服务端事务内校验来源、封面、容量和版本
→ 小程序推荐位生效
```

### 12.3 严重违规处理

```text
候选菜 / 推荐 / 图片资源
→ 违规处理
→ 选择动作和严重级别
→ 影响预览
→ 输入确认词并执行
→ 违规处理记录
→ 异步复制链任务
→ 失败项安全重试
```

### 12.4 配置维护

```text
能力配置
→ 读取当前配置
→ 编辑主模型、参数或受控提示词
→ 使用平台默认或编辑受控提示词
→ 校验、变量预览或测试运行（按需诊断）
→ 确认模型、提示词、积分和限额变化
→ 填写原因并保存
→ 当前配置被原子替换并立即生效
→ 调用记录验证运行结果
```

平台策略、图片审核、积分规则、生成校验策略和微信配置同样读取当前配置后直接保存，不使用草稿、发布、配置预览或历史版本流程。

### 12.5 饭局问题排查

```text
饭局列表
→ 饭局详情和状态时间线
→ 检查最终菜品快照
→ 查看采购清单
→ 检查清单项和分享状态
→ 复制业务 ID 反馈给用户
```

### 12.6 用户偏好画像核对

```text
小程序用户
→ 用户详情
→ 偏好画像
→ 核对画像更新时间和当前更新状态
→ 查看打卡贡献及其他来源数量摘要
→ 区分“用户设置”与“根据使用记录归纳”
→ 复制请求 ID 交给技术人员排查聚合失败
```

管理端只核对结果和运行状态，不修改画像、不替用户维护忌口，也不展示打卡原图和完整证据明细。

### 12.7 用户内容违规处理

```text
用户菜品或用户菜谱
→ 查看私有详情并记录访问审计
→ 确认违规对象是菜品还是菜谱
→ 违规处理影响预览
→ 填写原因并确认
→ 写处理记录并通知用户
→ 核对历史饭局和采购快照保持不变
```

### 14.1 不新增页面能力的冻结结果

以下能力不继续扩展 28 页菜单，第一版按下列方式落实：

- 推荐位不增加配置页。第一版只有 `home_featured` 一个推荐位，最多同时在线 5 条；推荐契约按固定枚举和容量校验。
- 偏好画像聚合权重、时间衰减和“不知道吃什么”的非模型召回、过滤阈值不提供后台编辑。第一版由服务端常量维护，变更需要代码评审和回归。生成结果是否匹配标准菜品索引和食材词库由 P28 的独立当前开关控制，不改变上述召回阈值。
- 打卡记录不增加独立菜单。图片资源和审核结果分别在 P12、P13 查询；打卡违规处理合并到 P11，使用 `targetType=checkin`、`action=soft_delete_checkin`，软删除打卡并保留积分流水与管理员审计。
- 跨对象操作审计不增加独立菜单。P02、P11、P14、P17、P18、P20、P21、P25、P26 的详情中按权限展示对象审计标签；未来确有跨对象检索需求时再单独评审菜单。

### 14.2 默认角色需要同步的口径

- GVA 角色、菜单、按钮和 API 权限均可配置，以下只是默认模板，不是业务代码固定授权。
- 自动注入的第一个管理员拥有全部当前及以后新增的 `orderfood` 页面、按钮和 API 权限。
- 微信配置默认只授予超级管理员；其他角色需要分别配置 `wechat-config:read` 和 `wechat-config:update`。
- 运营管理员可以维护官方菜品、推荐和基础数据；默认看不到用户菜品和用户菜谱，AI 供应商、模型、能力默认只读。
- 提示词正文查看、编辑和测试权限默认只授予超级管理员；运营管理员只看来源和哈希摘要。
- 内容安全管理员默认可以查看用户菜品和菜谱的私有详情，并执行普通违规处理、禁用用户和下线推荐，但默认不能删除复制链。
- 偏好画像默认只对超级管理员开放；内容安全、运营和客服不能从普通用户详情权限推导出画像权限。
- 客服角色在已授权页面全程只读，默认看不到用户菜品和用户菜谱。
- 如果审核决定让运营管理员调整积分，必须显式增加 `points:adjust`，不能通过页面可见性推断。
