# 用户长期偏好

## 语言与表达

- 默认使用中文沟通和书写项目级 AI 文档

## 文档组织偏好

- 不希望在多个工具目录中重复维护同一份 project rule
- 更倾向于 `AGENT.MD + aiDoc/` 的单一真源结构
- 更偏好 harness engineering 风格的分层文档设计
- 更偏好“讲解型示例”，而不是纯模板式示例

## Go 代码偏好

- 持久化模型字段需要完整 GORM 列定义，包含列名、数据库类型、空值或默认值、必要索引和数据库注释
- 业务表名保持简短；`orderfood` 模块使用 `of_` 前缀
- 新增代码需要方法注释和关键逻辑注释，结构体字段说明写在字段同行
- API 方法需要完整 Swagger 注释，成功响应必须标注具体数据模型，不能只写通用响应外壳
- GORM 与数据库集成测试使用 MySQL 8，不使用 SQLite 替代；测试库必须与开发、生产库隔离并自动清理

## 记忆管理偏好

- 不仅要保留长期记忆，也要记录每次用户提出的业务需求
- 业务记忆应独立存放，不能混入长期偏好
