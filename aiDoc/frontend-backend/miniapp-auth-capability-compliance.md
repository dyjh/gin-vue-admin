# 微信身份、能力开关与小程序发布合规基线

## 1. 文档定位

本文冻结以下跨端规则：

- 小程序启动后自动取得微信登录 `code`，由后端兑换微信身份并签发业务令牌。
- 平台可以整体开启或关闭增强能力，默认值为关闭；开启后所有增强功能统一开放。
- 不提供单用户或单项增强功能开关。
- 平台具备最高优先级的紧急停用开关。
- 用户增强能力关闭时，积分、积分流水、打卡奖励和打卡后的偏好分析同时关闭。
- 小程序发布包中不得出现 AI 相关静态字样、路径、文件名、变量名、接口字段或接口路径。
- 相关入口名称、按钮名称、说明和计费提示由后端按当前用户动态下发。

本文是 `order-food-contract-baseline.md` 的专项补充。发生冲突时，身份初始化、能力开关、积分联动和发布包命名以本文为准。

## 2. 微信身份初始化

### 2.1 启动流程

小程序每次冷启动执行：

1. `App.onLaunch` 立即调用 `wx.login`。
2. 客户端取得一次性 `code`。
3. 客户端调用 `POST /api/miniapp/v1/auth/wx-login`。
4. 后端使用 AppID、AppSecret 和 `code` 调用微信 `jscode2session`。
5. 后端以 `openid` 查找或创建小程序用户；存在 `unionid` 时一并保存。
6. 后端校验用户禁用状态。
7. 后端计算当前用户的有效能力策略。
8. 后端签发业务访问令牌，并返回用户资料和运行时配置。
9. 页面请求统一等待启动认证 Promise 完成，不允许每个页面各自重复登录。

### 2.2 `code` 安全边界

- `code` 只允许提交给业务后端，客户端不能直接提交或保存 `openid`。
- `code` 不写本地缓存、数据库、业务日志、错误日志或埋点。
- 后端日志只记录追踪 ID、结果状态和微信错误码，不记录 `code`、`session_key`。
- 登录接口不接受客户端传入 `openid`、`unionid` 或业务 `userId`。
- 同一个 `code` 重复兑换时返回稳定错误，不创建重复用户。
- 访问令牌失效后，客户端通过单飞锁重新执行一次 `wx.login`，认证成功后只重放允许安全重试的请求。
- 登录失败时显示通用重试状态，不能降级成匿名身份继续调用个人业务接口。

### 2.3 身份字段

后端用户表至少包含：

- `public_id`：对客户端公开的业务用户 ID。
- `wechat_open_id`：按小程序 AppID 唯一，禁止返回客户端。
- `wechat_union_id`：可空，禁止返回客户端。
- `status`、`disabled_reason`。
- `last_login_at`。
- `created_at`、`updated_at`。

`wechat_open_id` 建立唯一索引。后台列表默认不展示完整 `openid`；具备诊断权限时也只展示脱敏值。

## 3. 能力策略模型

### 3.1 平台策略

平台策略包含：

| 字段 | 含义 | 默认值 |
| --- | --- | --- |
| `defaultEnabled` | 平台增强能力总开关 | `false` |
| `suspended` | 全局紧急停用，优先级最高 | `false` |
| `pointsLinked` | 增强能力关闭时同步关闭积分体系 | `true`，第一版不可修改 |
| `version` | 配置版本，用于缓存失效 | 递增 |
| `updatedBy` | 最近修改管理员 | - |
| `updatedAt` | 最近修改时间 | - |

第一版上线时必须初始化为：

```text
defaultEnabled = false
suspended = false
pointsLinked = true
```

### 3.2 有效状态计算

```text
if platform.suspended:
  effectiveEnabled = false
else:
  effectiveEnabled = platform.defaultEnabled
```

平台总开关开启前，六项能力配置必须全部就绪；开启后六项能力统一可用。不存在单用户例外，也不存在单项能力启停。

积分有效状态：

```text
pointsEnabled = effectiveEnabled
```

业务接口必须在 Service 层再次校验有效状态。客户端隐藏入口不能代替服务端鉴权。

## 4. 能力目录与动态文案

### 4.1 中性能力编码

小程序与小程序 API 只使用以下中性编码：

| 编码 | 业务用途 | 默认展示名称示例 |
| --- | --- | --- |
| `dish_extract` | 从文本或图片整理菜品字段 | 识别菜品 |
| `cover_create` | 生成菜品封面 | 生成封面 |
| `meal_suggest` | 按条件给出菜品或组合建议 | 帮我推荐 |
| `prep_sequence` | 生成跨菜品备菜顺序 | 备菜顺序 |
| `taste_profile` | 打卡后异步整理偏好证据 | 无直接入口 |

默认名称只是后台初始化数据，不写入小程序发布包。

### 4.2 运行时配置

登录和启动聚合接口返回：

```json
{
  "policyVersion": 1,
  "enhancedFeaturesEnabled": false,
  "pointsEnabled": false,
  "features": []
}
```

为用户开启后，`features` 按需返回：

```json
{
  "code": "cover_create",
  "title": "生成封面",
  "actionText": "生成封面",
  "description": "根据菜品信息生成封面图",
  "enabled": true,
  "pointCost": 8,
  "freeQuota": 0,
  "costHint": "每次消耗 8 积分",
  "freeQuotaHint": null,
  "sortOrder": 20
}
```

规则：

- 未对当前用户开启的能力不返回名称、说明和计费文案。
- 小程序根据 `code` 绑定已有交互容器，但所有可见文字来自后端。
- 客户端不得为动态字段设置含 AI 字样的兜底文案；配置缺失时直接隐藏入口。
- 后端返回的文案应支持版本化和缓存失效。
- 后台可以修改展示名称，但正式环境启用前必须经过内容与合规确认。

## 5. 关闭状态下的业务表现

当 `effectiveEnabled=false`：

- 菜品识别、封面生成、菜品建议和备菜顺序入口全部隐藏。
- 对应接口拒绝执行，不能仅依赖客户端隐藏。
- 后端不向客户端返回这些能力的名称、说明、模型信息或费用。
- “我的”页面不展示当前积分。
- 积分流水入口和页面不可进入。
- 积分汇总、流水和能力使用记录接口返回稳定的“功能不可用”错误。
- 做菜打卡继续正常保存。
- 打卡响应 `rewardGranted=false`、`rewardAmount=0`。
- 不创建打卡奖励积分流水。
- 不触发打卡图片偏好分析或自然语言偏好摘要任务。
- 历史积分余额和流水保留在数据库中，不清零、不删除；重新开启后恢复展示。
- 已在执行中的外部任务按任务状态收口；已扣积分但不能交付结果时必须幂等退还。

## 6. 小程序发布包零敏感字样约束

### 6.1 禁止范围

最终上传到微信的发布包中，以下位置不得出现 AI 相关字样：

- WXML、WXSS、JS、JSON 中的静态文案。
- 页面目录、文件名和组件名。
- 变量名、函数名、常量名、事件名和注释。
- API 路径、请求字段、响应字段和本地缓存键。
- 图片、字体和其他资源文件名及其 URL。
- Mock、工具脚本、README、预览文件等被误打包的开发文件。
- 供应商、模型名称和模型标识。

至少扫描以下词形：

```text
AI
ai（独立词或路径片段）
人工智能
大模型
模型生成
智能生成
智能推荐
```

普通单词中连续字母恰好包含 `ai`，例如 `detail`，不视为命中。

### 6.2 路径迁移

当前代码至少需要完成：

```text
pages/ai/what-to-eat          -> pages/ideas/what-to-eat
pages/ai/what-to-eat-detail   -> pages/ideas/what-to-eat-detail
pages/meal/prep-ai            -> pages/meal/prep-guide
```

同时修改：

- `app.json` 页面注册。
- 页面跳转路径。
- 请求封装和 Mock 路由。
- 组件属性、事件名和状态变量。
- 本地与远程资源文件名。
- 分享路径和埋点事件名。

### 6.3 小程序接口中性化

小程序调用的接口路径必须中性化：

```text
/assist/dish-extraction
/assist/dish-covers
/meal-suggestions
/meal-suggestions/{suggestionId}
/prep-plans
/feature-usages
/runtime-config
```

后台管理接口、数据库表和服务端内部代码可以保留准确的 AI 技术术语，因为它们不进入小程序发布包；但不能把这些内部字段直接序列化给小程序。

### 6.4 打包门禁

发布前必须：

1. 使用 `project.config.json` 的 `packOptions.ignore` 排除 `.preview`、开发工具、文档及生产不需要的 Mock。
2. 对实际上传包而不只是源码目录执行敏感词和敏感路径扫描。
3. 扫描结果必须为 0。
4. 检查动态配置关闭时，审核账号无法看到入口、文案、积分或流水。
5. 检查相关接口在关闭状态下由后端拒绝执行。

扫描脚本放在小程序发布包之外，避免扫描规则本身进入发布包。

## 7. 后台管理要求

后台至少提供：

- 平台默认状态开关，默认关闭。
- 全局紧急停用操作及二次确认。
- 每项能力的供应商、模型、限额、费用和动态文案配置。
- 按有效状态筛选用户。
- 展示用户当前有效状态及计算来源。
- 配置变更审计和紧急停用审计。
- 所有配置读取当前值后直接保存并立即生效；不提供配置草稿、发布或历史版本。

后台管理员修改平台默认状态或全局紧急停用时，必须展示影响用户数量和积分入口变化。

## 8. 最低测试范围

- 冷启动自动登录并只兑换一次 `code`。
- 并发页面请求只等待同一个登录 Promise。
- 无效、过期、已使用 `code` 不创建重复用户。
- 同一 `openid` 并发首次登录只创建一条用户记录。
- 平台默认关闭、默认开启。
- 全局紧急停用覆盖所有用户。
- 平台开启后六项能力全部可用，不存在单用户或单项能力例外。
- 配置切换后旧缓存失效。
- 关闭状态下所有受控接口均被后端拒绝。
- 关闭状态下打卡成功但不奖励积分、不写奖励流水。
- 关闭状态下历史积分不展示但数据保留。
- 开启状态下积分扣减、失败退款和流水恢复正常。
- 实际微信上传包敏感词及敏感路径扫描结果为 0。

## 9. 当前落实结果

2026-07-26 收口结果：

- 页面、组件、状态变量、事件名、接口封装和远程资源映射已完成中性化。
- `.preview`、`tools` 和 `README.md` 已通过 `project.config.json` 明确排除在上传包之外。
- 入口是否展示由登录时下发的整体开关和功能目录决定；平台关闭时不请求积分与使用记录接口。
- 功能标题、按钮名称和说明统一使用后端运行时配置，配置缺失时隐藏入口。
- 发布门禁脚本位于上传包之外：`node aiDoc/miniApp/tools/validate-package-compliance.cjs`。

最终是否允许上传，以该脚本对实际上传范围的扫描结果为准，命中数必须为 `0`。
