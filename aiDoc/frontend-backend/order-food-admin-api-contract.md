# “来干饭”后台管理端 API 契约

## 1. 文档信息

- 版本：`1.2.0`
- 日期：2026-07-25
- 状态：已冻结，可进入实现
- 管理端 API 清单：`../admin/api.json`
- 管理端 PRD：`../prd/order-food-admin-web-prd.md`
- 菜单与页面实施基线：`../prd/order-food-admin-menu-page-review.md`
- 小程序跨端基线：`order-food-contract-baseline.md`

本文负责冻结管理端的认证边界、路由风格、请求响应、权限码、幂等、错误语义、指标口径和关键工作流。字段、页面与接口的机器可读清单以 `../admin/api.json` 为准。

## 2. 已冻结设计原则

1. 管理端统一使用 `/api/orderfood`，沿用 GVA 管理员 JWT 和 Casbin API 权限。
2. 小程序业务令牌不能访问管理端；管理员令牌不能伪装成小程序用户。
3. 资源使用复数名词；资源状态动作使用清晰子资源，例如 `/recommendations/{id}/publish`。
4. 列表使用 `GET` 查询参数，创建使用 `POST`，完整编辑使用 `PUT`，软删除使用 `DELETE`。
5. 后台不修改用户饭局点选、最终份数和采购项；饭局与采购接口只读。
6. 列表只返回摘要；详情和敏感内容独立查询。影响预览只用于积分调整和违规处理，不用于配置保存。
7. 所有 ID 在 JSON 中使用字符串，禁止把数据库自增 ID 暴露为跨端契约。
8. 所有日期时间使用 ISO 8601 并包含时区；服务端业务自然日固定为 `Asia/Shanghai`。
9. 所有写操作记录管理员、目标、变更摘要、请求 ID 和幂等键；仅产品明确要求原因的操作记录必填原因，推荐发布和删除草稿不强制填写原因。
10. 积分规则、生成校验策略、图片审核、平台策略、AI 能力和提示词均读取当前配置后直接保存并立即生效，不提供草稿、发布、配置预览、历史版本、恢复或回滚。

## 3. 传输与统一响应

### 3.1 请求头

```http
Authorization: Bearer <gvaAdminToken>
X-Request-Id: <traceId>
X-Idempotency-Key: <idempotencyKey>
Content-Type: application/json
```

- `X-Request-Id` 可由前端传入；缺失时由服务端生成。
- 所有响应通过 `X-Request-Id` 回传追踪 ID。
- `X-Idempotency-Key` 在所有管理端写操作中必填。
- 官方菜品编辑页通过 `/official-dish-covers` 上传或选择平台封面。管理端上传不调用阿里云审核，固定记录 `admin_upload/official_dish_cover/not_required`，但必须校验文件、场景和平台归属。

### 3.2 成功响应

```json
{
  "code": 0,
  "data": {},
  "msg": "ok"
}
```

### 3.3 失败响应

```json
{
  "code": 20901,
  "data": {
    "currentStatus": "published",
    "currentVersion": 3
  },
  "msg": "目标状态已经变化，请刷新后重试"
}
```

- 失败时 `data` 默认是 `null`。
- 状态冲突可以返回目标的最新 `currentStatus` 和 `currentVersion`。
- 响应不得包含供应商原始密钥、SQL、堆栈或微信敏感字段。

## 4. 分页、筛选和排序

统一分页查询参数：

```text
page       number  默认 1，最小 1
pageSize   number  默认 20，只允许 20、50、100
sortBy     string  只能选择接口声明的白名单字段
sortOrder  string  asc|desc
```

统一分页响应：

```json
{
  "page": 1,
  "pageSize": 20,
  "total": 42,
  "list": []
}
```

规则：

- 默认排序为 `createdAt DESC, id DESC`。
- 分类、标签、单位和推荐位默认使用 `sortOrder ASC, id ASC`。
- 模糊搜索只作用于接口明确列出的字段。
- 时间筛选使用 `createdFrom`、`createdTo`，均为包含边界。
- 数组查询参数使用重复参数或逗号分隔字符串，后端统一绑定为字符串数组。
- 导出不在第一版通用开放；需要导出时必须新增独立接口和权限码。

## 5. 幂等与并发

### 5.1 幂等作用域

服务端幂等记录唯一键：

```text
administratorId + endpointId + idempotencyKey
```

同时保存：

- 标准化请求体 SHA-256。
- 处理状态：`processing|succeeded|failed`。
- HTTP 状态、业务码和成功响应摘要。
- 创建时间和过期时间。

### 5.2 重复请求

- 同键同参数、首次已成功：返回首次业务结果，不重复执行。
- 同键同参数、首次处理中：返回 HTTP `409`、业务码 `20904`。
- 同键不同参数：返回 HTTP `409`、业务码 `20902`。
- 业务校验失败不缓存为成功结果；客户端修正参数后必须使用新幂等键。
- 普通幂等记录保留 24 小时。

### 5.3 永久业务唯一约束

幂等记录过期后，下列业务仍依赖数据库唯一约束：

- 同一管理员调整请求只生成一组积分流水。
- 同一饭局只生成一份采购清单。
- 同一推荐源在同一推荐位置不能同时存在多条在线记录。
- 同一配置更新使用当前版本完成一次原子替换；服务端内部版本号只用于并发、缓存和审计关联，不提供历史版本查询。
- 同一违规处理执行请求只能创建一个处理任务。
- 同一订阅消息发送记录的自动重试次数不超过配置上限。

### 5.4 乐观并发

配置、状态和高风险动作请求必须携带 `expectedVersion`。目标版本不一致时返回 `20901` 和最新版本，不能覆盖他人修改。

## 6. HTTP 状态与业务错误码

| HTTP | 业务码 | 含义 |
| ---: | ---: | --- |
| 400 | 20001 | 管理端参数格式或字段校验失败 |
| 401 | 20101 | 管理员登录已过期 |
| 403 | 20301 | 缺少 API 或按钮权限 |
| 403 | 20302 | 管理员账号不可用 |
| 404 | 20401 | 管理端资源不存在或不可见 |
| 409 | 20901 | 目标状态或版本冲突 |
| 409 | 20902 | 幂等键对应的请求参数不同 |
| 409 | 20903 | 资源已生成、已发布或已存在 |
| 409 | 20904 | 相同幂等请求仍在处理中 |
| 409 | 20905 | 资源正在被引用，不能删除或停用 |
| 422 | 22201 | 图片内容审核未通过 |
| 422 | 22202 | 图片资源无效、未审核通过或用途不匹配 |
| 422 | 22203 | 积分调整后余额小于 0 |
| 422 | 22204 | 配置组合无效或缺少可用依赖 |
| 422 | 22205 | 违规处理动作或影响范围不合法 |
| 422 | 22206 | 服务端未配置数据加密密钥，请配置 `orderfood.identity-key` 并重启服务 |
| 422 | 22207 | 服务端数据加密密钥格式错误，须为32字节密钥的Base64编码 |
| 429 | 22901 | 管理操作过于频繁 |
| 502 | 25001 | 外部供应商调用失败 |
| 504 | 25004 | 外部供应商调用超时 |
| 500 | 25000 | 管理端未预期服务器错误 |

接口专属允许错误码在 `../admin/api.json` 的 `errors` 字段中声明。后端不得对所有业务失败统一返回 HTTP 200。

### 6.1 错误码唯一注册入口

所有可对外返回的错误类型和业务码统一定义在：

```text
server/errors/error.go
```

规则：

- `server/errors/error.go` 是错误码常量、默认消息和所属端的唯一真源。
- `orderfood` 的 API、Service、Model 和定时任务中禁止散落裸数字错误码。
- `../admin/api.json` 和 `../miniApp/api.json` 只镜像对外契约，不负责定义 Go 常量。
- 对外稳定错误码必须显式赋值，不能依赖 `iota` 顺序；后续插入新错误不能改变已有数值。
- Service 返回 `server/errors` 中的类型化错误；API 层通过 `c.Error(err)` 交给统一错误中间件，不重复拼装失败响应。
- HTTP 状态映射由统一错误处理完成，业务层不能把所有错误降级为 HTTP 200。
- 生产环境只返回安全消息；错误上下文和堆栈只进入安全日志。

错误码分区冻结为：

| 范围 | 所属端 | 说明 |
| ---: | --- | --- |
| `10000-19999` | 全局共享 | 基础设施和无法归属单端的系统错误 |
| `20000-29999` | 后台管理端 | `/api/orderfood` 和其他管理员业务错误 |
| `40000-49999` | 前台小程序 | `/api/miniapp/v1`、公共分享和小程序用户业务错误 |

当前小程序 `40001-47005` 保留不迁移；管理端使用本文的 `20000-29999`，不得复用同名小程序错误码。

### 6.2 前台接口参数校验

`/api/miniapp/v1` 与 `/api/miniapp/v1/public` 的请求结构体在完成 Gin 绑定后，统一调用：

```go
utils.VerifyAll(&req)
```

实现文件：

```text
server/utils/front_validator.go
```

约束：

- API 层先执行 `ShouldBindJSON`、`ShouldBindQuery`、`ShouldBindUri` 或相应绑定，再执行 `utils.VerifyAll`。
- 请求结构体必须通过 `validate` 标签表达必填、长度、范围、枚举、数组唯一性和嵌套校验。
- 切片和嵌套对象必须正确使用 `dive`，不能只校验外层切片是否存在。
- 校验失败统一转换为前台参数错误 `40001`，并由全局错误中间件返回。
- 菜名、简介、备注、做法、AI 原始输入等自然语言字段必须标记 `checksql:"false"`，避免合法的引号、分号或自然语言 `and/or` 被字符串扫描误杀。
- `checksql:"false"` 不代表跳过数据库安全：所有 SQL 仍必须使用参数绑定，禁止拼接用户输入。
- Service 层继续执行所有权、状态机、唯一性和跨字段业务校验；`VerifyAll` 不能替代业务校验。

## 7. 核心状态枚举

### 7.1 饭局

```text
collecting -> closed -> confirmed -> completed
     |           |
     +-----------+-> cancelled
```

- `collecting`：点餐中。
- `closed`：点餐已关闭，等待创建者确认菜单。
- `confirmed`：菜单已确认、采购清单已生成，饭局仍进行中。
- `completed`：创建者手动结束，属于终态。
- `cancelled`：取消，属于终态。
- 同一创建者最多存在一个 `collecting|closed|confirmed` 饭局。
- 管理端只读，不提供推进、取消或完成饭局的接口。

### 7.2 图片审核

```text
pending|passed|rejected|failed|not_required
```

`failed` 表示审核接口异常或超时；`rejected` 表示明确违规、疑似风险或需要人工复核。

### 7.3 增强能力调用与计费

执行状态：

```text
pending|processing|succeeded|failed
```

计费状态：

```text
not_charged|charged|refund_pending|refunded
```

退款不是执行状态。失败退款必须表示为：

```json
{
  "executionStatus": "failed",
  "billingStatus": "refunded"
}
```

退款临时失败表示为：

```json
{
  "executionStatus": "failed",
  "billingStatus": "refund_pending"
}
```

后台任务自动重试到 `refunded`；管理端调用记录页不提供手工退款。

### 7.4 推荐、违规处理和消息

```text
RecommendationStatus: draft|published|offline
GovernanceJobStatus: pending|processing|partially_succeeded|succeeded|failed
SubscribeLogStatus: pending|sending|sent|failed
```

## 8. 仪表盘指标口径

查询范围只允许：

```text
today|last7Days|last30Days
```

时间范围按 `Asia/Shanghai` 自然日切分，结束时间为当前时刻。金额统一返回人民币元字符串和 `currency=CNY`，不使用浮点数直接表示金额。

| 指标 | 定义 |
| --- | --- |
| 新增用户 | `createdAt` 落在范围内的小程序用户数 |
| 活跃用户 | 范围内至少完成一次成功认证业务请求的去重用户数 |
| 新用户首次创建菜品率 | 范围内新增用户中，截至范围结束至少创建过一道未删除菜品的用户比例 |
| 可用菜品数 | 范围结束时状态为 `usable` 且未删除的菜品数 |
| 允许被发现菜品数 | 范围结束时 `discoverable=true`、`usable`、未删除且非来源锁副本的菜品数 |
| 推荐中菜品数 | 范围结束时状态为 `published` 的推荐记录数 |
| 创建饭局数 | `createdAt` 落在范围内的饭局数 |
| 加入人数 | 范围内新增饭局参与关系数，创建者不重复计入 |
| 确认菜单数 | `confirmedAt` 落在范围内的饭局数 |
| 采购清单生成数 | `createdAt` 落在范围内的采购清单数 |
| 打卡数 | `createdAt` 落在范围内且未删除的打卡数 |
| 获得、消耗、退款积分 | 范围内对应积分流水 `amount` 的绝对值合计 |
| AI 成功率 | `succeeded / (succeeded + failed)`；处理中和前置拦截不进入分母 |
| AI 失败率 | `failed / (succeeded + failed)` |
| AI 平均耗时 | 已进入外部调用且终态记录的 `durationMs` 平均值 |
| AI 估算成本 | 范围内调用记录 `estimatedCostCny` 合计 |
| 生效用户数量 | 当前账号正常且平台总开关实际生效的用户数；紧急停用或总开关关闭时为 0 |
| 违规处理任务异常数 | 状态为处理中、部分成功或失败的违规处理任务数 |
| 图片审核失败数 | 范围内 `rejected|failed` 审核记录数 |
| 订阅消息失败数 | 范围内终态为 `failed` 的发送记录数 |
| 待退积分异常数 | 当前 `billingStatus=refund_pending` 的调用记录数 |
| AI 连续失败告警 | 供应商或模型达到连续失败阈值的告警数；只提示人工处理，不自动关闭总开关 |

比率分母为 0 时返回 `null`，不能返回字符串 `"NaN"` 或虚构的 0%。

## 10. 权限码与默认角色

权限码格式：

```text
orderfood:<resource>:<action>
```

示例：

```text
orderfood:user:read
orderfood:user:disable
orderfood:points:adjust
orderfood:recommendation:publish
orderfood:governance:cascade
orderfood:provider:credential-write
orderfood:ai-usage:sensitive-read
```

逻辑角色代码：

```text
orderfood_super_admin
orderfood_operator
orderfood_governance
orderfood_support
```

逻辑角色不假设 GVA 数字 authority ID；初始化时映射到实际 authority。角色、菜单、按钮和 API 权限均可在 GVA/Casbin 中配置，以下角色只是默认模板，业务代码不能按角色名隐式授权。

### 10.1 超级管理员

- 拥有 `orderfood:*`。
- 只有此角色默认拥有偏好画像读取、供应商与图片审核凭证写入、严重违规复制链处理和系统策略修改权限。
- 自动注入的第一个管理员绑定此角色，并自动获得以后新增的全部 `orderfood` 权限。

### 10.2 运营管理员

- 可读仪表盘、用户、积分、饭局、采购和运营数据。
- 可维护分类、标签、单位、官方菜品和推荐。
- 默认不能执行人工积分调整；需要时必须单独授予 `orderfood:points:adjust`。
- 可维护非密钥 AI 基础配置，但不能写供应商凭证或查看敏感 AI 原文。

### 10.3 内容安全管理员

- 可读全部用户菜品与菜谱的私有详情、候选菜品、推荐、媒体、审核、违规处理记录和图片审核生效配置。
- 可关闭发现、下线推荐、软删除违规菜品或菜谱、处理违规打卡和禁用用户。
- 默认不能查看用户偏好画像，也不能编辑、保存或测试图片审核配置。
- 严重违规复制链操作默认只授予超级管理员；如需下放必须单独授权。

### 10.4 客服只读

- 可读用户、积分流水、饭局、采购、AI 调用元数据、通知和订阅发送记录。
- 不可查看 AI 原始输入输出、供应商凭证、图片审核原始返回。
- 不拥有任何 `create|update|delete|publish|adjust|govern|retry` 权限。

模型页的供应商基础选项和实时模型目录统一使用 `model:read`，模型新增/编辑按钮分别只要求 `model:create`、`model:update`，不跨菜单依赖 `provider:read`；能力编辑仍要求 `model:read`，提示词正文读取、编辑和测试分别使用 `prompt:read|update|test`。依赖权限不完整时前端隐藏按钮，后端仍必须拒绝请求。

## 11. 高风险工作流

### 11.1 积分调整

1. 前端调用 `/point-adjustments/preview` 获取当前余额和调整后余额。
2. 提交时携带预览返回的 `previewToken`、原因和幂等键。
3. 服务端事务锁定用户当前积分行。
4. 校验预览令牌、余额和用户版本；扣减后不得小于 0。
5. 更新余额并写不可变积分流水和管理审计。

### 11.2 推荐发布

1. 推荐记录只能从可发现用户菜品或可用官方菜品创建。
2. 推荐列表页不提供新建入口；创建请求由候选池或官方菜品页面带入固定来源。
3. 发布和重新发布只调用 `/recommendations/{id}/publish`，不生成预览令牌、不填写发布原因。
4. 发布事务实时校验来源仍可用、图片合法、推荐位容量和版本；冲突返回 `20901`。
5. 手动下线必须填写原因；来源关闭发现、编辑、删除或被违规处理时使用固定系统原因自动下线。
6. 删除草稿只需一次确认和版本，不要求原因。

### 11.3 违规处理

1. `/governance-actions/preview` 返回受影响推荐、源菜品、用户副本和通知数量。
2. 执行请求必须回传 `previewToken`、违规类型、原因、动作集合和 `expectedVersion`；动作包含 `delete_copy_chain` 时还必须回传确认词“确认处理复制链”，服务端必须精确校验。
3. 从推荐精选发起时同时回传 `entryRecommendationId`。服务端必须校验该推荐的 `sourceType + sourceDishId` 与 `targetType + targetId` 一致，治理记录的实际目标是源菜品，影响快照保留入口推荐 ID。
4. 处理用户或官方源菜品时，同一事务自动下线该源头关联的全部在线推荐，不只处理入口推荐。推荐的普通“下线”接口仍只影响当前推荐。
5. 普通动作在事务中完成；用户源菜品软删除同时移出现有菜谱关系，并将点单中或已关闭点单的饭局候选标记为不可选，已确认饭局和采购历史快照不变。
6. `delete_copy_chain` 在存在用户复制菜品时创建异步处理任务，支持分批、断点和失败重试；没有复制菜品时在当前事务完成。
7. 用户内容处理写站内通知；官方源菜品本身不生成用户通知，复制链任务仍按实际受影响用户菜品通知。
8. 重试只处理失败项目，不能重复通知或重复删除成功项目。
9. 每个目标结果独立记录，任务最终状态允许 `partially_succeeded`。

### 11.4 平台策略与能力配置

1. 平台策略、AI 能力和提示词的读取接口返回当前配置及当前版本，更新接口携带当前版本和变更原因。
2. 更新通过字段及依赖校验后原子替换当前配置并立即生效，不生成草稿、发布任务或预览令牌。
3. 每项能力只有一个与模态兼容的主模型；图片能力选择图片生成模型，文字能力选择普通文本模型。
4. 提示词变量和输出 JSON Schema 由系统固定；校验、变量渲染和测试针对管理员当前提交的内容。
5. 提示词测试只使用管理员数据，不扣积分、不写用户业务结果，测试成功不是保存前置条件。
6. 配置模块不提供历史版本查询、恢复或回滚；内部版本号只用于并发控制、缓存失效和审计关联。
7. 平台总开关开启前六项能力必须全部就绪，开启后整体开放，不提供单用户或单项开关。
8. 全局紧急停用使用独立接口，只改变紧急状态，不夹带平台文案或普通配置修改。

### 11.5 供应商连接测试

- 连接测试只使用服务端保存的安全凭证引用。
- 响应只返回结果分类、耗时和安全错误摘要。
- 不返回请求头、完整供应商响应或密钥。
- `GET /ai-model-provider-options` 只返回模型页所需的供应商 ID、名称、类型和启用状态；`GET /ai-providers/{providerId}/models` 使用服务端凭据读取供应商兼容 `/models` 接口，只返回安全归一化后的模型标识和是否已配置，不返回原始响应。
- 两个模型选项接口都使用 `model:read`，不要求用户拥有供应商管理菜单的 `provider:read`。
- 模型新增和编辑表单必须使用该接口下拉选择模型；加载失败允许重试，但不回退为自由文本输入。
- 超时返回 `25004`，认证或供应商错误统一映射为 `25001`。
- 供应商和模型新增后固定停用，普通新增/编辑 DTO 不包含 `enabled`；启停只能使用独立状态接口并填写原因。
- 供应商启用前要求当前配置连接测试成功；模型启用前要求所属供应商已启用且配置完整。
- 被当前能力引用的模型以及仍有启用模型或能力引用的供应商不能直接停用。

### 11.5.1 微信订阅场景

- 场景目录由服务端代码固定，管理端没有场景新增、删除接口；第一版仅有 `meal_status`，只用于参与者主动授权后的饭局最终确认或取消。
- `PUT /subscribe-scenes/{scene}` 只接收微信模板 ID、三个固定字段映射和可选期望版本；首次绑定固定停用，后续原位更新且不改变状态。启停只能调用独立状态接口。
- 关闭点餐、发起人自己的操作、用户禁用和 AI 退积分不创建订阅发送记录。

### 11.6 生成建议索引校验

1. 菜品索引、食材词库和校验策略使用独立的读取、维护权限。
2. 校验开关更新携带当前版本和原因，校验通过后立即替换当前策略。
3. 开关只控制标准菜名、菜系和食材词库匹配；字段结构、分类、标签、单位和配料步骤一致性始终校验。
4. 开关开启时，同一笔生成使用首次失败后固定额外尝试 1 次，两次失败才退款且不占免费次数；关闭时只尝试 1 次，失败同样退款。
5. 两次尝试共用同一请求 ID、使用记录和计费过程，不得重复扣分。
6. 生成结果写入独立快照，不进入推荐池或个人菜品库；仅在用户主动保存某一道时创建个人未公开菜品。
7. 新环境默认关闭索引校验；索引工作区返回就绪状态和阻塞原因。
8. 保存开启前必须校验：启用菜品数不少于单次生成可能要求的最大菜品数；启用菜品引用的分类和食材均启用；菜品名称与别名在菜品索引内归一化后无冲突；食材名称与别名在食材词库内归一化后无冲突。
9. 未就绪时保存开启返回稳定配置错误；保存关闭始终允许。
10. 当前策略为开启时，任何会破坏就绪状态的菜品、食材或分类修改必须被拒绝，并返回安全的引用影响摘要；管理员需先保存关闭策略。

## 12. 敏感字段

下列字段永远不出现在列表响应：

- 微信 `openid`、`unionid`、`session_key` 原值。
- AI 供应商密钥或可直接取回密钥的值。
- 用户 AI 原始输入、图片原始元信息和完整模型输出。
- 阿里云审核的完整原始响应。

详情响应规则：

- 微信身份仅返回脱敏摘要。
- 供应商只返回 `credentialConfigured` 和不可逆掩码标签。
- AI 敏感内容需要 `orderfood:ai-usage:sensitive-read`。
- 审核原始摘要需要 `orderfood:moderation:sensitive-read`。
- 清除 AI 敏感内容只清除业务载荷，保留请求 ID、模型、费用、状态和审计字段。

## 13. 前端实现约束

- `web/src/api/orderfood/` 按领域拆分，不在 Vue 页面直接调用 axios。
- 页面根据权限码决定按钮可见性，但后端仍必须执行 Casbin 校验。
- 状态冲突展示服务端最新状态并提供刷新。
- 高风险动作先调用预览接口，确认弹窗展示服务端返回的影响数据。
- 写请求在用户再次编辑表单后生成新的幂等键。
- 同一提交失败重试时沿用原幂等键。
- 列表切换筛选后重置到第 1 页。

## 14. 契约测试最低范围

- 28 个页面引用的接口全部存在，一级直达页面、菜单分组、页码、路由名和顺序与产品实施基线一致。
- method、path、权限码和 Swagger 完全一致。
- 四类角色的允许与拒绝用例。
- 所有写接口缺少幂等键时返回 `20001`。
- 同键同参重放、同键异参冲突、处理中冲突。
- `expectedVersion` 并发更新冲突。
- 分页、最大页大小和稳定排序。
- 列表不泄露敏感字段。
- 用户基础详情不能旁路返回积分、AI 调用、通知、偏好画像或操作审计数据。
- 用户菜品、菜谱私有详情和偏好画像读取必须使用独立权限并先写访问审计。
- 图片审核配置的凭据不回显；连接测试和图片测试使用服务端当前已保存配置，测试结果不作为保存门槛。
- 微信配置的 AppSecret 不回显；首次配置和更换 AppID 必须提交 AppSecret，后续留空表示保留，保存后立即供登录和订阅消息使用。
- 积分调整事务和不可负余额。
- 推荐发布、自动下线和重复发布。
- 违规处理预览令牌、异步复制链部分失败及重试。
- 各配置读取回显、直接保存、并发冲突和缓存版本失效。
- 供应商连接测试脱敏。
- 饭局和采购接口只读。
- 仪表盘时间范围、分母为零和金额精度。
