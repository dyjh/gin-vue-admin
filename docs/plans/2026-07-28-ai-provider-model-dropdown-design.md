# AI 供应商模型下拉设计

## 目标

模型管理新增和编辑不再允许管理员手工输入供应商模型标识。管理员先选择供应商，页面再展示该供应商实时返回的模型下拉，以减少拼写错误和无效配置。

## 方案选择

- 固定白名单：实现简单，但会随供应商发布和下线模型迅速过时。
- 可输入下拉：兼容性高，但仍无法阻止错误模型标识。
- 实时供应商目录：复用供应商兼容 `/models` 接口，选项与当前凭据实际可见范围一致。

采用实时供应商目录。第一版支持的百炼、DeepSeek 和 OpenAI 均通过当前 OpenAI 兼容连接层访问；后端使用已保存的 API Key 发起请求，前端不接触凭据。

## 数据流

1. 模型页面使用 `GET /api/orderfood/ai-model-provider-options` 读取供应商基础选项，不调用供应商管理列表接口。
2. 管理员打开新增或编辑模型弹框并选择供应商。
3. Web 请求 `GET /api/orderfood/ai-providers/{providerId}/models`。
4. 两个选项接口都校验 `orderfood:model:read`；实时目录接口读取供应商配置并请求其 `/models`。
5. 后端只提取合法模型 ID，执行长度校验、空白与控制字符过滤、去重、排序和数量限制。
   模型归属以供应商 `/models` 的实际返回为准，不按模型名称做厂商白名单过滤。
6. 后端查询当前供应商已配置模型并为选项添加 `configured` 标记。
7. 前端将已配置项置灰；编辑时当前模型保持可选。选择模型后自动填充提交所需的名称和模型标识。

## 错误与安全

- 凭据缺失、鉴权失败和供应商异常统一返回管理端供应商错误，不返回原始响应正文。
- 超时使用稳定错误码 `25004`，其他供应商失败使用 `25001`。
- 加载失败展示重试入口，不回退成自由文本输入。
- 供应商已下线当前模型时，编辑弹框仍展示当前配置，管理员可保持不变或改选实时可用模型。

## 新建与编辑表单

- 弹框采用“状态说明、基础配置、能力参数、计费参数、补充信息”五段式结构。
- 创建后的默认停用说明放在表单顶部的独立状态卡中；编辑时同一位置说明启用状态不会改变。
- 表单内容区独立滚动，底部取消和提交按钮始终可见。
- 供应商与模型、能力与上下文、输入与输出价格采用双列布局，小屏时自动回落为单列。
- 备注作为独立的补充信息区，不再与创建状态提示混排。

## 验证

- 连接器单元测试覆盖鉴权头、过滤、去重和排序。
- Go API 包编译检查，Swagger 与机器契约校验。
- Web 生产构建。
- 通过 WSL 启动 Air 和 `npm run serve`，在浏览器验证选择供应商、模型加载、已配置项禁用和错误重试状态。
